## 功能新增／調整

### 1. 首次啟動引導與本機 Agent 自動發現

新安裝或尚未完成初始化的使用者，首次啟動會進入三步引導：

1. 檢查 Git；可以暫時跳過，之後在需要 Git 的操作前再處理。
2. 檢查 Node.js、npm、npx；三項均需通過才能繼續。
3. 掃描並診斷本機可用 Agent；診斷成功的 Agent 會自動加入「Agent 管理」，再選擇預設 Agent、模型和權限模式，預覽後套用至全部內建 Workflow。

已完成初始化的使用者，可以在「設定 → 一般 → 引導與 Workflow」重新執行引導；其中「設定預設項目」只會批次調整內建 Workflow，不會覆寫自訂 Workflow。

> [!NOTE]
> 引導不會自動安裝 Git、Node.js 或 Agent。缺少工具時會提供官方安裝指引；安裝或登入後重新檢測即可。Agent 必須通過本輪診斷，才會列入可選清單。

### 2. Composer 草稿箱與待傳送佇列

Direct 工作階段執行中可以繼續輸入，內容可以先加入待傳送佇列，再按需要傳送。佇列最多保留 10 筆，支援自動或手動傳送、暫停與恢復、調整順序、編輯、刪除和立即傳送；停止工作階段或重新啟動用戶端後，未傳送內容仍會保留。

新增草稿箱，最多儲存 20 筆草稿。草稿會保留正文、檔案引用、角色和附件引用，取回到輸入框後再決定是否傳送。儲存失敗不會清空正在編輯的內容，附件也不會因為停止工作階段或切換頁面而遺失。

### 3. Multica 需求看板與結果交接

行內版的「需求管理」進一步完善遠端任務協作：

1. 可以依開發、測試類型篩選，並依任務名稱搜尋；開發任務完成後，相關測試任務會顯示「已就緒」並優先排在待辦清單前面，需要建立 DPMS 需求的任務會顯示「DPMS」提示。
2. Workflow 中被指定的節點可以分階段回傳交付快照，後續任務可在上游尚未完成時拉取說明；收尾節點最後彙整整個工作項目。任務完成後，也可以在原工作階段繼續補充並更新交付說明。
3. 上游交付說明尚未產生時，對話中會顯示處理卡片，可以繼續等待、手動提供資訊或跳過這次拉取。
4. 已完成或失敗的任務可以「重新執行」，原記錄會移回待辦清單，並顯示「重新執行」標記。
5. 在 Multica 網頁發起角色或 Workflow 分享後，用戶端可以在背景接收並重新整理對應清單，不需要在桌面端重複匯入。

### 4. 角色管理擴充與 WeAPM 內建角色

「上下文管理 → 角色管理」現在支援直接選擇一個或多個 Markdown 檔案匯入，也支援選擇資料夾批次匯入；每批最多處理 5,000 個檔案，匯入結果會保留每個檔案的成功或失敗原因。自訂角色清單改為完整顯示，不再分頁。

WB 管道新增唯讀的 WeAPM 內建角色，可使用 WeAPM CLI 查詢 Trace 和 Log，協助定位慢呼叫、錯誤、逾時和例外堆疊。

> [!NOTE]
> WeAPM 角色僅在 WB 管道提供，需要內部 WeAPM 服務、網路環境和 `weapm` CLI；查詢操作不會修改伺服器端資料。

### 5. IM 遠端介入與 Feishu 授權體驗

IM 整合設定改為依管道獨立展開的卡片，連線狀態、授權、綁定和通知偏好更容易分別管理。Feishu 授權時可以選擇既有應用程式或建立新應用程式，也可以在設定中切換應用程式；遠端介入的回答會在重試、重新連線和延遲回呼後保持一致，無法繼續處理的回呼會以後續訊息顯示。

> [!WARNING]
> **更換 Feishu 應用程式會清除目前的私訊綁定**
> 更換應用程式會取代目前授權並清除既有私訊綁定。完成授權後，請使用新應用程式對應的帳號再次向機器人傳送私訊。升級後的 IM 資料無法由舊版用戶端直接讀取；如需保留降級能力，請在升級前備份應用程式資料。

### 6. Workflow 畫布與桌面顯示設定

「設定 → 外觀」新增「介面縮放」，支援 `50%–250%` 的整個用戶端縮放，也可以使用 `Ctrl+滾輪`、`Ctrl+加號/減號` 和 `Ctrl+0` 調整或恢復預設值。

Workflow 作者態和執行態共用「自動／橫向／縱向」版面方向偏好；執行圖和編輯器都支援全螢幕檢視，進入全螢幕後保留目前草稿和檢查器，按 `Esc` 即可離開。

## 體驗最佳化

### 1. 更容易找到並復原工作階段

側欄新增跨工作區的「最近工作階段」區，依活動時間合併顯示，點選即可直接開啟對應工作階段；對話搜尋選取尚未載入的結果時，也會補出正確的側欄列並定位到目標。

Direct 工作階段啟動時會繼續等待 ACP 真正就緒，不再在 Agent 仍在啟動時誤報失敗；已確認的終止錯誤仍會正常顯示。背景重新整理、分頁和切換工作區時，已顯示的工作階段不會被延遲結果覆寫。

### 2. 檔案、附件與輸入狀態更穩定

工作區檔案、執行產物、工作階段附件和 Git 檔案分頁共用複製路徑、開啟所在資料夾、引用到對話等操作，並保留檔案原始來源；草稿和佇列中的附件引用也能跨頁面復原。從搜尋結果開啟工作階段後，側欄會同步展開並保持定位。

長文字輸入、IM 對話捲動和右側工作區切換更加穩定；Direct 啟動、佇列調度、附件預覽和本機檔案引用的異常會保留在對應範圍內，不再擴散為整個工作階段或工作區的錯誤。

### 3. 其他穩定性改進

1. Workflow 圖在橫向、縱向切換和全螢幕進出時重新適配正確的畫布範圍，減少連線、節點和側欄互相遮擋。
2. 最近工作階段和任務清單採用有界分頁與漸進載入，清單較大時不會一次讀取全部歷史。
3. 完善 Direct 工作階段復原、待處理介入結算和遠端審批狀態同步，減少已處理請求重新出現或任務狀態停留在舊值的情況。

## 0.21.1 相對於 0.21.0 的小幅最佳化

### 1. 首次引導支援稍後設定

執行環境檢查通過後，Agent 檢測完成或失敗時可點選「稍後設定」進入主畫面，之後再到設定中完成 Agent 設定；即使沒有可用的 Agent，也可以先進入應用程式。重新啟動後會保留這項選擇和先前跳過 Git 的設定。

### 2. 側欄導覽與近期工作階段更穩定

最佳化固定導覽、工作區、近期工作階段和執行記錄的對齊與選取狀態。近期工作階段支援與工作區清單一致的展開和操作，重新整理後仍會保留目前分組的選取位置。清單透過「顯示更多」分頁載入，工作區和近期工作階段清單收合後再展開時會恢復第一批內容。

### 3. 官方網站文件與下載入口更新

官方網站和 Demo 頁面統一使用 MALING 品牌，新增知識庫文件閱讀頁和依平台區分的下載選單；文件切換、窄螢幕版面和下載入口更加穩定。
