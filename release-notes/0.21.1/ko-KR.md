## 새로운 기능 및 변경 사항

### 1. 첫 실행 안내와 로컬 Agent 자동 검색

새로 설치했거나 초기 설정을 완료하지 않은 사용자는 처음 실행할 때 3단계 안내를 보게 됩니다.

1. Git을 확인합니다. 지금은 건너뛰고 Git이 필요한 작업을 할 때 설정할 수 있습니다.
2. Node.js, npm, npx를 확인합니다. 세 항목을 모두 통과해야 계속할 수 있습니다.
3. 사용 가능한 로컬 Agent를 검색하고 진단합니다. 진단에 성공한 Agent는 “Agent 관리”에 자동으로 등록되며, 기본 Agent·모델·권한 모드를 선택하고 미리 본 뒤 모든 기본 제공 Workflow에 적용할 수 있습니다.

초기 설정을 완료한 사용자는 “설정 → 일반 → 안내 및 Workflow”에서 다시 실행할 수 있습니다. “기본값 구성” 작업은 기본 제공 Workflow만 일괄 조정하며 사용자 지정 Workflow를 덮어쓰지 않습니다.

> [!NOTE]
> 안내 과정이 Git, Node.js 또는 Agent를 자동으로 설치하지는 않습니다. 도구가 없으면 공식 설치 안내를 제공하므로 설치하거나 로그인한 뒤 다시 검색하세요. Agent는 이번 진단을 통과한 경우에만 선택 목록에 표시됩니다.

### 2. Composer 초안과 전송 대기열

Direct 세션이 실행 중이어도 계속 입력하고 메시지를 전송 대기열에 넣어 나중에 보낼 수 있습니다. 대기열은 최대 10개를 보관하며 자동·수동 전송, 일시 중지와 재개, 순서 변경, 편집, 삭제, 즉시 전송을 지원합니다. 세션을 중지하거나 클라이언트를 다시 시작해도 보내지 않은 내용은 남아 있습니다.

새 초안 보관함에는 최대 20개의 초안을 저장할 수 있습니다. 본문, 파일 참조, 역할, 첨부 파일 참조를 보존하고 입력창으로 가져온 뒤 전송 여부를 결정할 수 있습니다. 저장에 실패해도 편집 중인 내용은 지워지지 않으며 세션 중지나 페이지 이동으로 첨부 파일이 사라지지 않습니다.

### 3. Multica 요구사항 보드와 결과 전달

내부 버전의 “요구사항” 페이지에서 원격 작업 흐름을 개선했습니다.

1. 개발·테스트 유형으로 필터링하고 작업 이름으로 검색할 수 있습니다. 개발 작업이 완료된 테스트 작업에는 “준비 완료”가 표시되고 대기 목록 앞에 배치됩니다. DPMS 요구사항이 필요한 작업에는 “DPMS” 표시가 나타납니다.
2. 지정된 Workflow 노드는 중간 전달 스냅샷을 보낼 수 있어 후속 작업이 상위 작업 완료 전에도 내용을 가져올 수 있습니다. 마지막 노드는 전체 작업 항목을 요약합니다. 완료 후에도 원래 대화에서 전달 내용을 보완하고 갱신할 수 있습니다.
3. 상위 작업의 전달 내용이 아직 준비되지 않았으면 대화 안의 카드에서 계속 기다리거나 직접 정보를 입력하거나 이번 가져오기를 건너뛸 수 있습니다.
4. 완료되었거나 실패한 작업을 “다시 실행”할 수 있습니다. 원래 행은 대기 목록으로 돌아가고 새 작업에는 “다시 실행” 표시가 붙습니다.
5. Multica 웹에서 역할이나 Workflow를 공유하면 클라이언트가 백그라운드에서 받아 해당 목록을 갱신하므로 데스크톱에서 다시 가져올 필요가 없습니다.

### 4. 역할 관리와 기본 제공 WeAPM 역할

“컨텍스트 관리 → 역할 관리”에서 Markdown 파일을 하나 이상 직접 가져오거나 폴더를 한꺼번에 가져올 수 있습니다. 한 번에 최대 5,000개 파일을 처리하며 파일별 성공 또는 실패 이유를 결과에 남깁니다. 사용자 지정 역할은 페이지를 나누지 않고 한 목록에 모두 표시됩니다.

WB 채널에 WeAPM CLI로 Trace와 Log를 조회해 느린 호출, 오류, 시간 초과, 예외 스택을 조사할 수 있는 읽기 전용 기본 제공 WeAPM 역할을 추가했습니다.

> [!NOTE]
> WeAPM 역할은 WB 채널에서만 사용할 수 있으며 내부 WeAPM 서비스, 네트워크 환경, `weapm` CLI가 필요합니다. 조회 작업은 서버 데이터를 변경하지 않습니다.

### 5. IM 원격 개입과 Feishu 인증

IM 통합 설정을 채널별로 접고 펼칠 수 있는 카드로 정리하여 연결 상태, 인증, 바인딩, 알림 설정을 각각 관리할 수 있습니다. Feishu 인증에서는 기존 앱을 선택하거나 새 앱을 만들 수 있고 나중에 앱을 바꿀 수도 있습니다. 원격 개입 답변은 재시도·재연결·늦게 도착한 콜백 이후에도 일관되게 유지되며, 더 이상 적용할 수 없는 콜백은 후속 메시지로 표시됩니다.

> [!WARNING]
> **Feishu 앱을 바꾸면 현재 개인 채팅 바인딩이 삭제됩니다**
> 앱을 교체하면 인증이 바뀌고 기존 개인 채팅 바인딩이 삭제됩니다. 새 앱을 인증한 뒤 해당 계정으로 봇에 개인 메시지를 다시 보내세요. 업그레이드된 IM 데이터는 이전 클라이언트에서 직접 읽을 수 없습니다. 다운그레이드 가능성을 유지하려면 업그레이드 전에 앱 데이터를 백업하세요.

### 6. Workflow 캔버스와 데스크톱 표시 설정

“설정 → 모양”에 “인터페이스 확대/축소”를 추가했습니다. 전체 클라이언트를 `50%–250%`로 확대하거나 축소할 수 있으며 `Ctrl+휠`, `Ctrl+더하기/빼기`, `Ctrl+0`으로도 조정하거나 초기화할 수 있습니다.

Workflow 작성 화면과 실행 화면은 “자동 / 가로 / 세로” 레이아웃 설정을 공유합니다. 실행 그래프와 편집기는 현재 초안과 검사기를 유지하는 집중형 전체 화면을 지원하며 `Esc`로 나갈 수 있습니다.

## 사용 경험 개선

### 1. 세션을 더 쉽게 찾고 복구

사이드바에 워크스페이스 전체를 아우르는 “최근 세션” 영역을 추가했습니다. 활동 시간순으로 합쳐 표시하며 행을 클릭하면 바로 열립니다. 검색 결과가 아직 로드되지 않은 세션이어도 올바른 사이드바 행을 만들어 대상 위치로 이동합니다.

Direct 세션을 시작할 때 ACP가 실제로 준비될 때까지 기다리므로 Agent가 시작 중인데 실패로 표시하지 않습니다. 확정된 종료 오류는 계속 표시됩니다. 백그라운드 새로 고침, 페이지 이동, 워크스페이스 전환 중에도 화면에 표시된 세션이 늦은 응답으로 덮어써지지 않습니다.

### 2. 파일, 첨부 파일, 입력 상태 안정성

워크스페이스 파일, 실행 결과물, 세션 첨부 파일, Git 파일 탭에서 경로 복사, 파일 관리자에서 표시, 대화에 참조 등의 작업을 공통으로 사용하면서 원래 파일 출처를 유지합니다. 초안과 대기열의 첨부 파일 참조도 페이지를 넘어 복원할 수 있습니다. 검색에서 세션을 열면 사이드바가 함께 펼쳐지고 대상 위치를 유지합니다.

긴 텍스트 입력, IM 대화 스크롤, 오른쪽 워크스페이스 전환을 안정화했습니다. Direct 시작, 대기열 전송, 첨부 미리 보기, 로컬 파일 참조 오류가 해당 화면 안에 머물러 전체 대화나 워크스페이스 오류로 번지지 않습니다.

### 3. 기타 안정성 개선

1. Workflow 그래프는 방향을 바꾸거나 전체 화면에 들어갔다 나올 때 올바른 캔버스 범위에 맞춰져 선, 노드, 사이드바의 겹침을 줄입니다.
2. 최근 세션과 작업 목록은 제한된 페이지 이동과 단계적 로딩을 사용하여 큰 기록을 한 번에 읽지 않습니다.
3. Direct 세션 복구, 대기 중인 개입의 종료 처리, 원격 승인 상태 동기화를 개선하여 처리된 요청이 다시 나타나거나 오래된 작업 상태가 남는 문제를 줄였습니다.

## 0.21.1: 0.21.0 이후의 소규모 개선

### 1. 첫 실행 설정을 나중에 완료

환경 검사를 통과했다면 Agent 검색이 완료되거나 실패한 뒤 “나중에 설정”을 선택해 앱에 들어가고, 나중에 설정에서 Agent 구성을 완료할 수 있습니다. 사용할 수 있는 Agent가 없어도 진행할 수 있습니다. 다시 시작한 뒤에도 이 선택과 이전에 Git을 건너뛰기로 한 설정이 유지됩니다.

### 2. 사이드바 탐색과 최근 대화 안정화

고정 탐색 영역, 워크스페이스, 최근 대화, 실행 기록의 정렬과 선택 상태를 개선했습니다. 최근 대화에서도 워크스페이스 목록과 같은 펼치기와 행 작업을 사용할 수 있고, 새로 고침 후에도 현재 그룹의 선택 위치가 유지됩니다. 목록은 “더 보기”로 페이지 단위로 불러오며, 워크스페이스 또는 최근 대화 목록을 접었다가 다시 펼치면 처음 항목들로 돌아갑니다.

### 3. 웹사이트 문서와 다운로드 입구 업데이트

웹사이트와 Demo 페이지의 브랜드를 MALING으로 통일하고 지식 베이스 문서 읽기 페이지와 플랫폼별 다운로드 메뉴를 추가했습니다. 문서 전환, 좁은 화면 레이아웃, 다운로드 입구가 더 안정적으로 동작합니다.
