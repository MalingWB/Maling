## 新機能・機能変更

> [!IMPORTANT]
> このバージョンではローカル設定が移行されます。0.21.x では移行後の設定を読み込めません。旧バージョンに戻す可能性がある場合は、アップデート前にアプリのデータをバックアップしてください。

### 1. ワークフローの実行グラフで現在のノードを再試行、または失敗したノードから再実行

会話からワークフローの実行グラフを開き、対象のノードを右クリックします。

1. **現在のノードを再試行**：現在のノードが異常により一時停止し、次の処理に進んでいない場合は、同じ Run の中でそのノードを再実行します。前回の会話や成果物は残ります。
2. **このノードから再実行**：失敗して終了した実行履歴（再実行可能な過去の履歴を含む）を選び、タスクに保存されている最新のワークフロー設定を使って、そのノードから新しい Run を開始します。元の Run は読み取り専用の履歴として残ります。

> [!WARNING]
> 失敗したノードから再実行すると、元の Run で進行中の処理は停止します。ワークスペースの変更、Git のコミット、実行済みの外部操作は元に戻りません。どちらの操作も通常のワークフローノードに限られ、AUTO モードや AI-DYNAMIC の内部ノードには対応していません。

### 2. Feishu と WeCom からワークフローを継続・復旧

Feishu または WeCom の個別チャットを連携すると、対象のワークフローが一時停止したときに操作カードが届きます。デスクトップアプリで手動停止した場合も対象です。

1. **ワークフローを継続する**：現在のノードが完了していなければ、そのノードを続けて実行します。
2. **ワークフローを復旧**：現在のノードは成功したものの次の処理に進んでいない場合、そのノードを再実行せず、すでに得られた結果を使って先へ進みます。

通知は既定で有効です。「設定 → 一般 → IM リモート介入と通知」で、チャネルごとに「ワークフロー続行リクエスト」を無効にできます。停止直後にカードが処理中と表示されたら、少し待ってから同じカードでもう一度操作してください。

> [!NOTE]
> リモート操作にはデスクトップアプリがオンラインである必要があります。今回のアップデートでは、IM からのワークフローの開始、停止、再実行には対応していません。アップデート前に一時停止していたワークフローのカードは一括送信されません。

### 3. 3 種類の Agent を追加し、初回セットアップを柔軟に

- 「Agent 管理」に DeepSeek Harness、ZCode、Qoder を追加しました。ZCode はコミュニティ製のアダプターを使用します。Windows ARM64 では組み込みの Qoder オプションは利用できません。組み込みの CodeBuddy は既定の表示名が WorkBuddy になり、既存の設定は保持されます。
- Agent の追加・編集時に「接続要件」から、必要なローカルコマンドと認証方法を確認できます。
- 初回セットアップでは引き続き Node.js、npm、npx を確認しますが、チェックに失敗してもローカルの Agent を検出できます。結果には、未インストール、実行環境の不足、診断の失敗が区別して表示されます。検出が完了または失敗した後は、利用可能な Agent がなくても「後で設定」を選んでメイン画面に進み、あとで設定を完了できます。

### 4. Vista と Meadow を追加し、ライトとダークで壁紙を個別に設定

「設定 → 外観」で、2 つの新しいテーマに切り替えられます。

- **Vista**：ライトは水彩の絵巻、ダークは黒と金の雪峰と星空です。青みがかった墨色とアプリコットゴールドは、それぞれの壁紙から採った配色です。
- **Meadow**：ライトは純白より柔らかな若葉色、ダークは松葉色で静かな春の夜を表現します。コードと Diff には明るめの背景を使い、読みやすさを保ちます。

Gold Band、Vista、Meadow には、合計 6 枚の壁紙が付属します。ライトとダークそれぞれで「テーマ壁紙」「カスタム」「無効」を選べます。カスタム壁紙は「塗りつぶし」と「収めて表示」に対応し、「最近使用した」の一覧から削除することもできます。

### 5. 会話をターン単位で移動し、入力欄の高さを調整

- 会話の左側にターンナビゲーションを追加しました。マーカーにポインターを合わせるとメッセージをプレビューし、クリックするとそのターンへ移動できます。まだ表示されていない過去のターンにも移動できます。
- ホーム画面と会話画面で、入力欄の上端をドラッグして高さを調整できます。別の会話に切り替えても高さは保持されます。下にドラッグして入力欄を小さくすると、自動調整に戻ります。

### 6. Multica からローカルのロールとワークフローをアンインストール

接続後、Multica のロール管理にある「Runtime」タブで、現在の実行環境にあるローカルのロールとワークフローをまとめて確認し、組み込み以外の項目をアンインストールできます。削除されるのはローカルのコピーだけで、Multica の共有カタログの内容は残ります。複数のリソース操作を続けて送信したときに、デスクトップアプリが待機中のリクエストをより早く処理します。

## 使い勝手の改善

### 1. サイドバーと会話をより使いやすく

- 「最近の会話」から実行履歴を展開したり、名前を変更したり、ピン留めしたりできます。サイドバーでは、各リストの末尾にあるボタンを押すと続きを読み込めます。実行履歴を更新しても選択は維持され、タスクが終わると処理中の表示が消えます。
- Markdown の表の本文にテーマの標準テキスト色を使うようにしました。ライト・ダークのどちらでも読みやすくなります。

### 2. 起動と Agent 接続の安定性を向上

- 特定の Agent の起動設定に問題があっても、アプリ全体の起動が妨げられなくなりました。WorkBuddy で後続のターンに起動方法が切り替わり、有効なローカル接続が切れる問題を修正しました。
- WebView の起動が失敗する一部の問題を修正しました。サポート外の環境では、プラットフォームに合ったアップデート手順が表示されます。新しい MCP クライアントから、組み込みの共有メモリ用ツールを検出しやすくなりました。

### 3. 公式サイトにナレッジベースとダウンロードメニューを追加

公式サイトと Demo のブランドを MALING に統一しました。公式サイトでナレッジベースを読めるほか、ダウンロードメニューからプラットフォームに合ったインストーラーを選べます。
