## 機能の追加・変更

### 1. 初回起動ガイドとローカル Agent の自動検出

新規インストール、または初期設定が完了していないユーザーは、初回起動時に 3 段階のガイドが表示されます。

1. Git を確認します。いったんスキップし、Git が必要な操作を行うときに設定することもできます。
2. Node.js、npm、npx を確認します。3 つすべてのチェックに合格する必要があります。
3. 利用可能なローカル Agent を検出・診断します。診断に成功した Agent は「Agent 管理」に自動登録され、既定の Agent、モデル、権限モードを選択して、確認後にすべての組み込み Workflow へ適用できます。

初期設定済みのユーザーは、「設定 → 一般 → ガイドと Workflow」から再実行できます。「既定値を設定」は組み込み Workflow をまとめて更新し、カスタム Workflow は上書きしません。

> [!NOTE]
> ガイドが Git、Node.js、Agent を自動インストールすることはありません。不足しているツールには公式のインストール案内が表示されるため、インストールまたはサインイン後に再検出してください。Agent は今回の診断に成功した場合だけ選択肢に表示されます。

### 2. Composer の下書きと送信キュー

Direct セッションの実行中も入力を続け、メッセージを送信キューに入れて後から送信できます。キューは最大 10 件で、自動／手動送信、停止と再開、並べ替え、編集、削除、今すぐ送信に対応します。セッションを停止したりクライアントを再起動したりしても、未送信の内容は保持されます。

新しい下書き箱には最大 20 件を保存できます。本文、ファイル参照、ロール、添付ファイル参照を保持し、入力欄に戻してから送信するかどうかを決められます。保存に失敗しても編集中の内容は消えず、セッション停止やページ移動で添付ファイルが失われることもありません。

### 3. Multica の要件ボードと成果の引き継ぎ

内製版の「要件」ページで、リモートタスクの処理を改善しました。

1. 開発・テストの種類で絞り込み、タスク名で検索できます。開発タスクが完了したテストタスクには「準備完了」が表示され、待機中の一覧で先に表示されます。DPMS 要件が必要なタスクには「DPMS」マークが表示されます。
2. 指定された Workflow ノードは途中の引き継ぎスナップショットを送信でき、後続タスクは上流タスクの完了前にも内容を取得できます。最終ノードは作業項目全体をまとめます。完了後も元の会話で引き継ぎ内容を追記・更新できます。
3. 上流の引き継ぎ内容がまだ生成されていない場合、会話内のカードから待機、手動入力、今回の取得をスキップできます。
4. 完了または失敗したタスクを「再実行」できます。元の行は待機中の一覧に戻り、新しいタスクには「再実行」マークが付きます。
5. Multica の Web 画面からロールまたは Workflow を共有すると、クライアントがバックグラウンドで受け取り、対応する一覧を更新できます。デスクトップから再度インポートする必要はありません。

### 4. ロール管理と組み込み WeAPM ロール

「コンテキスト管理 → ロール管理」では、1 つまたは複数の Markdown ファイルを直接インポートでき、フォルダーの一括インポートにも対応します。1 回の処理は最大 5,000 ファイルで、各ファイルの成功・失敗理由を結果に残します。カスタムロールはページ分割せず、一覧にまとめて表示されます。

WB チャネルに、WeAPM CLI で Trace と Log を検索し、遅い呼び出し、エラー、タイムアウト、例外スタックを調査できる読み取り専用の組み込み WeAPM ロールを追加しました。

> [!NOTE]
> WeAPM ロールは WB チャネルでのみ利用できます。内部 WeAPM サービス、ネットワーク環境、`weapm` CLI が必要です。検索操作はサーバー上のデータを変更しません。

### 5. IM リモート介入と Feishu 認証

IM 連携設定をチャネルごとの折りたたみカードに整理し、接続状態、認証、紐付け、通知設定を個別に管理できるようにしました。Feishu の認証では既存アプリを選択することも新しいアプリを作成することもでき、後からアプリを切り替えられます。リモート介入の回答は再試行、再接続、遅れて届いたコールバックの後も一貫して保持され、適用できないコールバックは後続メッセージとして表示されます。

> [!WARNING]
> **Feishu アプリを変更すると現在の個別チャット連携が解除されます**
> アプリを置き換えると認証が更新され、既存の個別チャット連携が削除されます。新しいアプリを認証した後、対応するアカウントからボットへもう一度個別メッセージを送ってください。更新後の IM データは旧クライアントから直接読み取れません。ダウングレードできる状態を保つには、更新前にアプリデータをバックアップしてください。

### 6. Workflow キャンバスとデスクトップ表示設定

「設定 → 外観」に「インターフェースのズーム」を追加しました。クライアント全体を `50%–250%` で拡大・縮小でき、`Ctrl+ホイール`、`Ctrl+プラス／マイナス`、`Ctrl+0` でも調整・リセットできます。

Workflow の編集画面と実行画面は「自動／横／縦」のレイアウト設定を共有します。実行グラフとエディターは集中表示用の全画面表示に対応し、現在の下書きとインスペクターを保持したまま `Esc` で終了できます。

## エクスペリエンスの改善

### 1. セッションを見つけて復元しやすく

サイドバーにワークスペース横断の「最近のセッション」を追加しました。活動時刻順にまとめて表示し、クリックすると直接開けます。検索結果がまだ読み込まれていないセッションでも、正しい行をサイドバーに補って対象へ移動できます。

Direct セッションの起動中は ACP が実際に準備完了になるまで待機し、Agent の起動中に失敗と誤表示しなくなりました。確定した終了エラーは引き続き表示されます。バックグラウンド更新、ページング、ワークスペース切り替えで、表示中のセッションが遅い応答に上書きされることもありません。

### 2. ファイル、添付ファイル、入力状態の安定性

ワークスペースのファイル、実行成果物、セッション添付ファイル、Git ファイルタブで、パスのコピー、ファイルマネージャーで表示、会話への参照などの操作を共通化し、元のファイルソースを保持します。下書きとキュー内の添付ファイル参照もページをまたいで復元できます。検索からセッションを開いたときは、サイドバーも展開して対象を維持します。

長文入力、IM 会話のスクロール、右側ワークスペースの切り替えを改善しました。Direct の起動、キュー送信、添付プレビュー、ローカルファイル参照のエラーは該当する画面に留まり、会話全体やワークスペース全体の失敗にはなりません。

### 3. その他の安定性改善

1. Workflow グラフは方向の切り替えや全画面の出入りで正しいキャンバス範囲に再適合し、エッジ、ノード、サイドバーの重なりを減らします。
2. 最近のセッションとタスク一覧は上限付きページングと段階的読み込みを使用し、大量の履歴を一度に読み込みません。
3. Direct セッションの復元、保留中の介入の確定、リモート承認の状態同期を改善し、処理済みの要求が再表示されたり、古いタスク状態が残ったりする問題を減らしました。
