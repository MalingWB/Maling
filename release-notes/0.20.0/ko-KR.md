## 기능 추가 및 변경

### 1. Feishu 원격 개입 및 알림 지원

이제 컴퓨터를 떠나 있어도 Feishu에서 권한 확인, Agent의 질문, 수동 검사를 처리하고 작업 결과 알림을 받을 수 있습니다.

사용 방법은 다음과 같습니다.

1. 「설정 → 일반 → IM 원격 개입 및 알림」에서 Feishu를 선택하고 권한을 확인한 뒤 QR 코드를 스캔하여 연결합니다.
2. QR 코드로 인증한 계정으로 봇에게 1:1 메시지를 보내 연결을 완료합니다.
3. 카드를 받으면 권한을 허용하거나 거부하고, 단일 선택·다중 선택·텍스트·직접 입력 답변을 작성하거나 수동 검사를 처리할 수 있습니다.

데스크톱, WeCom, Feishu 중 어느 한 곳에서 처리하면 연결되어 있고 해당 알림이 활성화된 다른 채널에도 결과가 동기화됩니다. Feishu 카드는 실제로 제출한 답변을 유지하고, 처리된 조작 항목은 비활성화합니다.

현재 연결한 계정과의 1:1 채팅만 지원하며, 하나의 봇은 한 대의 기기에 연결할 수 있습니다. 그룹 채팅이나 IM을 통한 작업 시작·중지·재실행은 지원하지 않습니다. 클라이언트가 오프라인이거나 컴퓨터가 절전 상태이거나 네트워크가 끊긴 경우 실시간 송수신을 보장할 수 없습니다. Lark 국제 버전은 아직 검증이 완료되지 않았습니다.

> [!WARNING]
> **업그레이드 전에 기존 카드와 다운그레이드 제한을 확인하세요**
> 이번 업그레이드에서는 이전 버전 IM 대화형 카드의 전송 기록과 관련 메시지 연결 정보를 정리합니다. 업그레이드 전에 받은 일부 카드가 더 이상 작동하지 않을 수 있으므로, 아직 처리하지 않은 요청은 데스크톱에서 처리하세요. 업그레이드된 IM 데이터는 이전 클라이언트에서 바로 읽을 수 없습니다. 다운그레이드 가능성을 남겨 두려면 업그레이드 전에 앱 데이터를 백업하세요.

### 2. Claude 네이티브 하위 Agent 및 백그라운드 작업 표시 개선

Claude가 하위 Agent를 실행하면 대화의 Agent 행에서 실행 상태를 확인하고, 오른쪽 작업 공간에서 읽기 전용 상세 정보를 열 수 있습니다. 동기 실행과 백그라운드 실행 하위 작업에 각각의 메시지, 권한 요청, 상태가 표시됩니다. 부모 턴이 끝나더라도 아직 실행 중인 하위 작업을 중단된 것으로 잘못 판단하지 않습니다.

백그라운드 활동 시간을 별도로 측정하여 긴 유휴 시간이 실행 시간에 포함되는 문제를 줄였습니다. 백그라운드 응답이 끝난 뒤에도 내용을 정상적으로 복사하고 인용할 수 있습니다.

> [!NOTE]
> Claude ACP `0.90.0` 이상이 필요하며, 이전 버전에는 업그레이드 안내가 표시됩니다. 대화를 다시 불러온 뒤 기존 하위 Agent를 이어서 실행하는 기능은 여전히 어댑터의 지원 범위에 영향을 받습니다. Token 합계에는 백그라운드 깨우기로 발생한 사용량이 포함되지 않으며, 패널에 관련 주의 사항이 표시됩니다.

### 3. 원격 요구사항 실행 및 결과 인계 개선

내부용 버전의 「요구사항 관리」에서 개발 작업, 테스트 작업, 원격 첨부 파일 처리를 개선했습니다.

1. 개발·테스트 작업별로 요구사항을 확인하고 실행할 수 있습니다. 해당 개발 작업이 아직 완료되지 않았다면 테스트 작업에 대기 안내가 표시되지만, 수동으로 실행할 수도 있습니다.
2. 「실행」을 클릭하면 요구사항 본문과 선행 작업의 인계 내용 등이 대화에 입력됩니다. 「보내기」를 클릭한 시점에 작업을 정식으로 가져옵니다.
3. 보내기 전에 원격 첨부 파일의 읽기 전용 목록을 확인할 수 있으며, 보낼 때 파일을 다운로드하여 이번 작업의 입력으로 사용합니다. 개별 첨부 파일의 다운로드가 실패해도 작업을 막지 않고, 누락 정보를 Agent에 전달합니다.
4. Direct 모드는 명확한 완료 출력을 기다린 뒤 완료 상태를 전달하여, 첫 응답이 끝났다는 이유만으로 요구사항이 일찍 닫히지 않도록 합니다. 워크플로 마지막 단계에서는 작업 항목 전체의 결과를 요약하여 후속 작업에 전달합니다.

### 4. 원격 Skill 다중 파일 양방향 동기화 지원

`SKILL.md`와 필요한 스크립트, 설명 등의 보조 파일을 포함한 Skill 전체를 로컬과 Multica 사이에서 동기화할 수 있습니다. Skill 전역 관리 페이지에서 「원격 SKILL 동기화」를 클릭하고 Multica에 연결한 뒤 작업 공간과 원격 Skill을 선택하면, 로컬로 가져오고 동기화 결과를 확인할 수 있습니다. 로컬 Skill을 원격으로 가져오려면 Multica 쪽에서 작업을 시작하세요.

원격 목록을 다시 불러오는 동안 이전 선택이 남아 있던 문제와 동기화 오류 후 복구가 불완전하던 문제를 수정했습니다.

> [!CAUTION]
> **덮어쓰기로 가져오면 Skill 디렉터리 전체가 교체됩니다**
> 로컬 Skill을 덮어쓰도록 선택하면 원격 디렉터리의 내용을 기준으로 적용하며, 원격에 없는 로컬 파일도 삭제됩니다. 유지할 로컬 변경 사항은 먼저 저장하세요.

### 5. 단축키로 대화 검색 열기 지원

`Ctrl+F`, macOS에서는 `Cmd+F`를 누르면 대화 검색이 열리고 입력란에 포커스가 이동합니다. 다시 누르면 현재 검색어가 선택되며, `Esc`로 닫으면 원래 조작 항목으로 돌아갑니다.

코드 편집기에서는 자체 파일 내 찾기가 우선 적용됩니다. 다른 대화상자, 메뉴 또는 선택기가 열려 있을 때는 대화 검색을 겹쳐 열지 않습니다.

### 6. Git 푸시 전 대상 확인

소스 관리에서 푸시하기 전에 실제 「로컬 브랜치 → 원격 / 대상 브랜치」를 표시하여 코드가 어디로 전송되는지 확인할 수 있습니다. 브랜치를 처음 게시할 때는 원격 저장소를 선택하고 업스트림을 설정할 수 있으며, 이미 업스트림이 있는 브랜치는 실제 추적 중인 대상으로 푸시합니다.

업스트림이 없는 브랜치는 「새 브랜치」로 표시하여 아직 게시하지 않은 브랜치를 동기화된 것으로 오해하는 일을 줄였습니다.

## 사용 경험 개선

### 1. 더 안정적인 기록 열람 및 대화 복원

위로 스크롤하여 읽는 중 자동 따라가기로 인해 다시 끌려 내려오는 문제를 수정했습니다. 현재 페이지가 화면을 채우지 못하는 경우에도 더 오래된 기록을 계속 불러올 수 있습니다. 대화에 다시 들어왔을 때 이미 처리한 질문이 이전 캐시 때문에 대기 상태로 돌아가지 않습니다.

대화를 이어 갈 때 해당 대화에 실제로 저장된 모델과 권한 설정을 유지하여, 이전 워크플로 설정 때문에 이어서 실행하지 못하는 문제를 줄였습니다.

### 2. 같은 이름의 첨부 파일이 이전 내용을 덮어쓰지 않음

이름이 같아도 내용이 다른 첨부 파일은 각각 저장되며, 나중에 업로드한 파일이 이전 첨부 파일과 미리보기를 덮어쓰지 않습니다. 긴 파일 이름의 저장을 개선하고, 경로가 너무 깊어 안전하게 저장할 수 없을 때 명확한 안내를 표시합니다.

### 3. Markdown 및 파일 작업 공간 사용성 개선

1. 대화에서 로컬 이미지를 미리 보거나 로컬 HTML 링크를 여는 문제를 수정했으며, 링크의 쿼리 매개변수와 페이지 내 위치를 유지합니다.
2. Markdown 실시간 미리보기가 패널의 사용 가능한 너비를 활용하여, 넓은 화면에서 불필요한 좌우 여백을 줄였습니다.
3. 내장 테마의 기본 편집기 글꼴 크기를 `13px`로 조정했습니다. 기존 사용자 지정 글꼴 크기는 유지됩니다.
4. 오른쪽 탭에서 렌더링 오류가 발생하면 해당 탭에서 다시 시도할 수 있으며, 전체 대화에 영향을 주지 않습니다. 여러 파일 트리가 함께 표시될 때의 안정성도 개선했습니다.

### 4. Token 중복 누적 수정

대화가 유휴 상태였다가 다시 이어질 때 Token 사용량이 중복 누적되던 문제를 수정했습니다. 기존 기록을 읽을 때도 식별 가능한 중복 누적을 바로잡습니다.

### 5. 기타 개선 사항

1. Windows에서 파일이 많은 커밋이나 병합 커밋을 확인할 때 변경 통계를 불러오지 못하는 문제를 수정했습니다.
2. 중국어 자동 언어 선택을 개선하여, 명시적인 간체·번체 표시를 지역 판정보다 우선합니다. 기존 수동 언어 설정은 유지됩니다.
3. 상주 세션 관련 다국어 문구를 보완하고, 일부 도구 설명이 제때 닫히지 않던 문제를 수정했습니다.
