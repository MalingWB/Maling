## 機能の追加・変更

### 1. Feishu のリモート介入と通知に対応

パソコンから離れているときも、Feishu で権限の確認、Agent からの質問、手動チェックに対応し、タスクの結果通知を受け取れるようになりました。

利用手順は次のとおりです。

1. 「設定 → 一般 → IM リモート介入と通知」を開き、Feishu を選択して権限を確認し、QR コードを読み取って接続します。
2. QR コードで認証したアカウントからボットに個別メッセージを送り、紐付けを完了します。
3. カードを受け取ったら、権限の許可・拒否、単一選択・複数選択・テキスト・自由回答の入力、手動チェックを行えます。

デスクトップ、WeCom、Feishu のいずれかで処理すると、接続済みで対応する通知を有効にしているほかのチャネルにも結果が同期されます。Feishu のカードには実際に送信した回答が残り、処理済みの操作項目は無効になります。

現在は紐付けたアカウントとの 1 対 1 の個別チャットのみ対応し、1 つのボットが接続できるデバイスは 1 台です。グループチャットや、IM からのタスクの開始・停止・再実行には対応していません。クライアントがオフラインのとき、パソコンのスリープ中、ネットワーク切断時は、リアルタイムの送受信を保証できません。国際版 Lark の検証はまだ完了していません。

> [!WARNING]
> **更新前に、既存カードとダウングレードの制限をご確認ください**
> 今回の更新では、旧版 IM の対話カードの配信記録と関連するメッセージの紐付けを削除します。更新前に受け取った一部のカードは利用できなくなる可能性があるため、未処理のリクエストはデスクトップで処理してください。更新後の IM データは旧版クライアントから直接読み取れません。ダウングレードできる状態を保つには、更新前にアプリのデータをバックアップしてください。

### 2. Claude ネイティブの子 Agent とバックグラウンドタスクの表示を改善

Claude が子 Agent を起動すると、会話内の Agent 行で実行状態を確認し、右側のワークスペースで読み取り専用の詳細を開けます。同期実行とバックグラウンド実行の子タスクには、それぞれのメッセージ、権限リクエスト、状態が表示されます。親ターンが終了しても、実行中の子タスクを中断と誤判定しなくなりました。

バックグラウンドの活動時間を個別に計測し、長いアイドル時間が実行時間に含まれる問題を軽減しました。バックグラウンドの応答が終了した後も、内容を通常どおりコピー・引用できます。

> [!NOTE]
> Claude ACP `0.90.0` 以降が必要です。旧版では更新を案内します。会話を再読み込みした後に既存の子 Agent を継続できるかどうかは、引き続きアダプターの機能に依存します。Token の集計にはバックグラウンドでの起動による消費が含まれず、パネルに注意が表示されます。

### 3. リモート要件の実行と成果の引き継ぎを改善

行内向け版の「要件」で、開発タスク、テストタスク、リモート添付ファイルの扱いを改善しました。

1. 開発・テストタスクごとに要件を確認して実行できます。対応する開発タスクが未完了の場合、テストタスクには待機を勧める案内が表示されますが、手動で実行することもできます。
2. 「実行」をクリックすると、要件の本文や上流タスクの引き継ぎ内容などが会話に取り込まれます。「送信」をクリックした時点で、正式にタスクを取得します。
3. 送信前にはリモート添付ファイルの読み取り専用一覧を確認できます。送信時にダウンロードされ、今回のタスクの入力として使用されます。個々の添付ファイルのダウンロードに失敗してもタスクは中断せず、不足情報が Agent に伝えられます。
4. Direct モードでは明確な完了出力を待ってから完了状態を返し、最初の応答が終わっただけで要件を早期に終了することを防ぎます。ワークフローの最終処理では、作業項目全体の成果をまとめ、後続タスクに引き継ぎます。

### 4. リモート Skill の複数ファイルの双方向同期に対応

`SKILL.md` と必要なスクリプト、説明などの補助ファイルを含む Skill 全体を、ローカルと Multica の間で同期できます。Skill のグローバル管理ページで「リモート SKILL を同期」をクリックし、Multica に接続してワークスペースとリモート Skill を選ぶと、ローカルに取得して同期結果を確認できます。ローカルの Skill をリモートにインポートする場合は、Multica 側から操作を開始してください。

リモート一覧の再読み込み中に古い選択が残る問題と、同期異常後の復元が不完全になる問題を修正しました。

> [!CAUTION]
> **上書き取得すると Skill ディレクトリ全体が置き換わります**
> ローカルの Skill を上書きする場合、リモートのディレクトリ内容が基準となり、リモートに存在しないローカルファイルも削除されます。残しておきたいローカルの変更は、先に保存してください。

### 5. ショートカットで会話検索を開けるように

`Ctrl+F`、macOS では `Cmd+F` を押すと、会話検索が開き、入力欄にフォーカスが移ります。もう一度押すと現在の検索語を選択し、`Esc` で閉じると元の操作項目にフォーカスが戻ります。

コードエディターでは引き続き独自のファイル内検索が優先されます。ほかのダイアログ、メニュー、セレクターが開いているときは、会話検索を重ねて開きません。

### 6. Git プッシュ前に送信先を確認

ソース管理でプッシュする前に、実際の「ローカルブランチ → リモート / 対象ブランチ」を表示し、コードの送信先を確認できるようになりました。ブランチを初めて公開するときは、リモートを選んで上流を設定できます。上流があるブランチは、実際に追跡している対象へプッシュします。

上流のないブランチには「新しいブランチ」と表示し、未公開のブランチを同期済みと誤認しにくくしました。

## エクスペリエンスの改善

### 1. 履歴の閲覧と会話の復元を安定化

上にスクロールしているときに自動追従で引き戻される問題を修正しました。現在のページが画面いっぱいに満たない場合も、さらに古い履歴を読み込めます。会話を開き直したときに、処理済みの質問が古いキャッシュによって未処理に戻ることもなくなりました。

会話を継続するときは、その会話に実際に保存されているモデルと権限設定を引き継ぎ、古いワークフロー設定によって継続に失敗する問題を軽減しました。

### 2. 同名の添付ファイルが履歴の内容を上書きしなくなりました

同じ名前でも内容が異なる添付ファイルは別々に保存され、後からアップロードしても過去の添付ファイルやプレビューを上書きしません。長いファイル名の保存を改善し、パスが深すぎて安全に保存できない場合は、明確な案内を表示します。

### 3. Markdown とファイルワークスペースの使いやすさを改善

1. 会話内のローカル画像のプレビューと、ローカル HTML リンクを開く際の問題を修正しました。リンクのクエリパラメーターとページ内の移動先も保持します。
2. Markdown のライブプレビューがパネルの利用可能な幅を使い、横幅の広い画面で不要な左右の余白を減らしました。
3. 内蔵テーマのエディターの標準文字サイズを `13px` に変更しました。既存のカスタム文字サイズは変更しません。
4. 右側のタブで描画エラーが発生しても、そのタブで再試行でき、会話全体に影響しなくなりました。複数のファイルツリーを同時に表示したときの安定性も改善しました。

### 4. Token の重複加算を修正

会話がアイドル状態になった後で再開すると、Token の消費が重複して加算される問題を修正しました。既存の記録を読み込む際も、識別できる重複加算を補正します。

### 5. その他の改善

1. Windows でファイル数の多いコミットやマージコミットを確認するときに、変更統計の読み込みに失敗する問題を修正しました。
2. 中国語の自動選択を改善し、明示的な簡体字・繁体字の指定を地域判定より優先するようにしました。既存の手動言語設定は変更しません。
3. 常駐セッションに関する多言語の文言を補完し、一部のツールチップがすぐに閉じない問題を修正しました。
