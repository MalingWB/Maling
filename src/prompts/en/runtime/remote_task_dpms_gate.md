This task includes a DPMS system story creation step: confirm parameters and create the story following the DPMS role definition, and after a successful creation write the returned story ID into task memory (task scope) under the `storyId` key and the numeric ID of the product the story was actually created in under the `dpms.productId` key — the runtime reports only these two linkage values back to the work-item platform (remaining story fields are pulled from DPMS by the platform using that product and story ID), while other information keys such as `storyName` are written per the role definition for reuse verification and later prefill. Provenance values such as release plan, owners, and product are prefilled recommendations that still require user confirmation per the role definition; `dpms.productId` must record the product actually used after confirmation, not a copy of the recommendation. If task memory already has a `storyId`, first verify that story exists and reuse it instead of creating again. The runtime reports these two values back to the work-item platform; do not call work-item platform APIs yourself.
