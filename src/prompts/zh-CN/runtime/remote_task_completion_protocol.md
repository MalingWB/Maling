本工作项关联远程工作项。回复末尾 info 为 `completion-output` 的代码围栏块是面向下游的**最终交付说明**（不是 run 日志；多次输出整体覆盖，只以最后一块为准），会随工作项传递给下游子任务作为执行上下文。内容按优先级覆盖：

- **核心信息（必须优先确保）**：构建与部署——构建出的包名/制品名（依赖包名、Docker 镜像名、安装包文件名等）、部署的环境（环境名及访问地址/命名空间/目标位置）、改动范围（极其精简，一两条即可，不展开细节）。前序节点（尤其是 CI/CD 节点）产出中已给出的构建/部署信息必须携带进你的块，即使并非本节点执行；本次交付不涉及构建或部署时明确写一句，不让下游无法区分「确实没有」与「遗漏未写」。
- 次要信息（篇幅允许时补充，不得挤占核心信息）：下游测试要点与注意事项、自测结论与已知边界、下游执行所需的环境/数据/账号、验证地址或分支。
- 正文 ≤2000 字符，超长会使完成请求被整体拒绝、工作项无法标记完成；详细的执行过程或大段材料写入工作区文件，块内只保留文件路径引用（行内代码格式）。

**直接对话执行时，该块是完成门控**：只有你的最终回复末尾附加此块，远程工作项才会被标记完成；未完成全部工作时不得输出此块。需要继续对话推进任务（等待确认、追问结果、多轮迭代）时正常回复即可，不要输出块。

**在工作流中执行时**（能看到前序链路或工作流上下文），该块不门控完成：收尾节点（产出就是任务的最终交付、不再被后续节点加工）在最终回复末尾输出此块；其他节点不输出——唯一例外是被指定承担阶段性上送职责的节点（配置了「交付上传」角色，或目标中带其声明标记）：此时即使产出还会被后续节点继续加工也输出，并注明这是阶段性快照、尚未最终完成（阶段性快照供下游任务在工作流结束前拉取提前启动）。节点需要以 JSON 裁决（如 `{"reason":…,"result":…}`）收尾时，把块放在裁决 JSON 之前的最后一条人类可读回复末尾——传递给下游的只有块，裁决 JSON 不会被采集。无论何种执行形态，块必须总结**整个工作项**：综合前序节点产出与附件得出，不得只写你自己节点的产物；阶段性快照按当前已产出内容综合并如实注明待完成部分；核心信息确实不可得时，对整体产出做简要总结即可。

**任务完成后的修订**：远程工作项已标记完成后，用户在会话中要求调整交付说明内容（如补充建议测试点、修正包名或环境）时，在回复末尾重新输出完整的新块——整块覆盖已存内容而非增量差异，核心信息必须保留；此次输出不改变任务的完成状态。用户没有要求调整时，完成后的对话正常回复即可，不要主动再输出块。

输出此块时格式必须精确如下——开头围栏 ``` 与 `completion-output` 写在同一行，不得把 `completion-output` 另起一行：

```completion-output
（交付说明正文，≤2000 字符）
```
