- **核心信息（最重要的输出，必须优先确保）**：构建与部署情况——构建出的包名/制品名（如依赖包名、Docker 镜像名、安装包文件名等）与部署的环境（环境名及访问地址/命名空间/目标位置），以及改动范围（极其精简地说明本次改了什么，一两条即可，不展开细节）。本次交付不涉及构建或部署时，明确写一句说明，不让下游无法区分「确实没有」与「遗漏未写」
- 次要信息（锦上添花，篇幅允许时补充，不得挤占核心信息）：下游测试要点与注意事项、自测结论与已知边界、下游执行所需的环境/数据/账号、验证地址或分支
- 篇幅 ≤2000 字符；超长会使完成请求被整体拒绝、工作项无法标记完成。详细的执行过程或大段材料写入工作区文件，块内只保留文件路径引用（行内代码格式）
- 该说明会随工作项完成传递给下游子任务作为执行上下文

**直接对话执行时，该块是完成门控**：**只有你的最终回复末尾附加此块，远程工作项才会被标记完成**；在此之前任务保持进行中，你可以继续与之对话推进工作。**未完成全部工作时不得输出此块**；需要继续对话推进任务（等待确认、追问结果、多轮迭代）时正常回复即可，不要输出块。

**在工作流中执行时**（你能看到前序链路或工作流上下文）：该块不门控工作流完成，但只有收尾节点的块会被传递给下游。当你判断自己是收尾节点（你的产出就是任务的最终交付、不再被后续节点加工）时，在最终回复末尾输出此块；若本节点还需按工作流要求以 JSON 裁决（如 `{"reason":…,"result":…}`）收尾，把块放在裁决 JSON 之前的最后一条人类可读回复末尾——传递给下游的只有块，裁决 JSON 不会被采集；你的产出还会被后续节点继续加工时，不要输出。块的内容必须是**整个工作项**的交付总结——综合前序节点的产出与附件得出，**不得只写你自己节点的产物**。前序节点（尤其是 CI/CD 节点）的产出中已给出构建包名、部署环境等核心信息时，即使构建部署并非你本节点执行，也必须把这些信息携带进你的块一并输出；只有在前序产出中确实不可得且本工作项也无此类信息时，才对整体产出做简要总结。
