# multica 接入外部角色：交付上传 / 交付拉取

M5-cf 引入的两个外部导入角色（非内置 profile），用于把 completion-output 的上送与拉取从「工作流结束才发生」提前到「工作流中段」：

- **交付上传**（`导入包/交付上传-upstream-upload.md`）：给开发任务工作流的中段节点用。角色正文内置声明标记 `<!-- gold-band:upstream-upload -->`（goal 直写该标记等效）——标记是**装配时产出资格声明**（M5-cg 产出侧门禁）：桌面端在节点启动装配 prompt 时按节点身份判定产出资格，带标记的中段节点被指定为 **Staged**（阶段性上送），收到「产出 completion-output 块」协议；未带标记的普通节点被指定为 **Prohibited**，收到的协议明确要求不产出块。Staged 节点完成本职产出后，在回复末尾输出 `completion-output` 块，桌面端在该节点成功边界把本轮最新块作为阶段性快照 PUT 到远程工作项（值变化才上送，重复跳过）；收尾节点（所有出边指向结束）被指定为 **Final**，收尾交付仍由 `/complete` 通道整体携带。
- **交付拉取**（`导入包/交付拉取-upstream-pull.md`）：给测试任务工作流的中段节点用。角色正文中的 `$upstream.completion-output` 令牌是拉取声明开关：节点启动时解析父工作项当前的 completion-output（附父状态行），注入首条 prompt 隐藏运行上下文的「上游交付说明」区段（会话内可展开审计），令牌本身从正文移除；父尚未产出时按「15s 起、×1.5 退避、上限 60s、总预算 15 分钟」轮询等待。

## 典型编排（开发-测试并行）

```
开发任务工作流:  [开发节点] → [构建/部署节点(配「交付上传」)] → [收尾节点]
                                  │ 阶段性快照 PUT
                                  ▼
                        multica 父工作项 completion_output
                                  │ 测试任务节点启动时拉取
                                  ▼
测试任务工作流:  [测试准备节点(配「交付拉取」)] → [执行/收尾节点]
```

测试任务在开发工作流结束前即可启动，替代原先「父 done 才能开始」的串行依赖。

## 使用前提

1. 两个任务都在 multica 建为工作项，且测试任务以开发任务为**父工作项**（拉取侧按 `parent_issue_id` 寻址父）。
2. 「交付拉取」所在任务必须是 multica 远程任务（本地普通任务没有 issue 绑定，令牌解析会直接报结构化错误）。
3. 角色是外部导入角色，不是内置 profile：复制 `导入包/` 下的 `.md` 文件到 `~/.gold-band/presets/profiles/`，或在角色管理中通过「导入文件夹」选择 `导入包/` 目录（本 README 不在导入包内，避免被当作角色扫描）。
4. 桌面端版本要求：产出资格按节点身份装配指定（M5-cg）与拉取侧隐藏区段注入均需 2026-10-26 之后的桌面端；更早版本上旧版「交付上传」角色会退化为「每个成功节点都上送」。**升级桌面端后需更新两个角色正文到新版**（均已更新）。
   - **不要直接重复「导入文件夹」**：导入对同名角色会新建副本（如「交付上传-2」），工作流节点仍引用旧条目，旧正文没有标记 → 上报节点被装配为 Prohibited（不产出、不上送）。
   - 正确做法：在角色管理中**编辑既有的「交付上传」「交付拉取」条目**，把 `导入包/` 下对应文件的正文整体粘贴替换后保存（条目不变，工作流引用保持有效）。
   - 标记是 HTML 注释，渲染视图不可见：确认是否更新到位请在**编辑视图**查看正文开头是否有 `<!-- gold-band:upstream-upload -->`。
   - direct 协议区段按任务在创建时刻冻结（`first-prompt-hidden-sections`）：升级前创建的任务重跑仍带旧协议文本，**验证新语义请用新建任务**；workflow/auto 不冻结协议区段，按节点身份在装配时逐节点注入，新建任务即生效。

## 行为口径

- 上传侧：收尾节点完成时的 `/complete` 通道仍是权威写入（最后写入覆盖）；中段快照只让下游更早看到值，不改变完成判定。
- 拉取侧：拿到的是节点启动时的快照，父后续覆盖不会自动刷新，重新运行该节点才会取新值；父工作项未完成时快照带阶段性提示，由角色按「先推进不依赖最终版本的部分」执行。
- 服务端约束（内网 2026-10-24 确认）：completion-output 单键 PUT 无状态门槛，上限 16000 runes；父字段非空即下发给子任务，不要求父 done。
