# Forge Spec（工作流生成草稿）

## 1. 一句话定义

Forge Spec 是工作流铸造的中间表示：LLM 对话收敛结论的结构化载体，经确定性编译为 `WorkflowDsl`。它是三件事的唯一事实源——对话的记忆（中断恢复）、流程图预览的数据源（图是 Spec 的投影）、编译的输入。

## 2. 结构

```jsonc
{
  "specVersion": "0.1",
  "name": "…",                 // 顶层名（单工作流时必收敛）
  "intent": "一句话流程意图",
  "sourceSkills": ["code-review"],   // 入口 B 来源 skill 引用
  "workflows": [
    {
      "name": "…",
      "stages": [
        {
          "id": "test-1",       // 系统分配的稳定身份（角色-序号），也是编译后的节点 id；新 stage 省略，合并后由系统补齐
          "role": "dev | test | review | plan | accept | {custom:{profileName}}",
          "goal": {"input":"…","output":"…","boundary":"…","acceptance":"…"}, // 字段身份与语言无关；值是用户语言
          "roleDefinition": "…", // custom 角色的职责正文（人格），与 goal 分离
          "profileId": "pf-…",  // 持久绑定仅由系统根据可信基线回填，模型不能授权改写其他角色
          "artifact": "…", "outputKind": "json|markdown|none",
          "schemaHint": {…}, "successCondition": "$.passed == true",
          "onFailure": "retry|manual-check|new-round|end", "manualCheck": false
        }
      ]
    }
  ],
  "openQuestions": [{"question":"测试失败后返回哪一步？","recommendation":"回到开发，沿用上次会话"}]
}
```

## 3. 关键语义

- **增量生长**：模型每轮只输出增量（`SpecDelta`），合并规则在 `src/forge/interview.rs`；全量状态由存档维护（`<task_dir>/forge/spec.json`，原子写）。模型的围栏已闭合而 JSON 只漏了结尾的 `}` / `]` 时按括号配平补全（它认为已经输出完，只差结尾）；截断在字符串里等无法确定原意的情况不应用。
- **stage 的稳定身份**：`id` 由系统在每轮合并后分配，形如 `角色-序号`（`plan-1`、`dev-2`、`test-3`、`review-4`、`accept-5`，自定义角色为 `custom-6`；序号按角色分别计，Spec 内唯一），模型省略或给出不可作节点名的值时补齐。增量只按 `id` 对齐——命中即整体覆盖，不带 `id` 或 `id` 不在基线中的一律是新 stage（不按位置猜测：协议只要求输出变更的 stage，按序号对齐会把修改落到错误的 stage 上）。`id` 同时是编译后的节点 id 和工作流编辑器画布上的节点名，所以用角色命名而不是纯序号；它在分配那一刻取自角色，之后角色变了 `id` 也不变——改名、插入、删除都不影响既有节点的身份。
- **基线随每条消息注入**：当前 Spec 存档作为隐藏区段「当前基线 Spec」随每条用户消息下发（角色是会话内不变的 system prompt，只承载协议规则与 Schema）。模型据此对齐增量、原样携带 `profileId`；修改存量工作流的会话首轮即拿到反投影基线。
- **角色与任务分离**：同一工作流内同名阶段共享一份定义，角色绑定以服务端存档或源模板为准，模型文本不能自行授权改写全局角色。全体使用者一起改名时保持 ID；阶段换到本工作流已有角色时沿用目标 ID，换到新角色则分离。不同模板不能同名（含 Multica 新导入）；只回收系统生成且已无引用的角色，手工和内置角色不回收。保留草稿而原模板已删除时，显式另存可按可信草稿重建生成角色。
- **编译**（`src/forge/compiler.rs`）：纯函数，stages→worker 节点（节点 id = stage id，内置角色引用 `pf-builtin-*`），onFailure→边映射，产物 100% 过 `ValidatedWorkflow`；custom 角色在保存链路铸造/更新后回填节点引用，并为缺绑定执行槽补默认 agent 绑定。校验一次报出全部问题（`forge/missing-goal-element` 等），不是只报第一个。
- **原位更新**：会话对应关系里仍有可原位更新的模板时，重新编译按节点 id 对齐回写——模型绑定、执行槽、权限与模板级配置保留，只覆盖 Spec 表达的字段（goal、角色、产物契约、成功条件、人工复核、链路顺序），模板名跟随 Spec；新增或未绑定的执行槽补默认绑定。内置模板允许从选择器发起对话式修改，但必须用不同的名称保存副本；副本以原定义和绑定为基底，保留未改动的成功/失败边与尝试/轮数上限。首次保存后会话绑定副本，后续修改不动原件。只有从未绑定的工作流默认新建。原件丢失、同一外部键被重新安装或原件已不能无损表达时，保存返回不可用；用户可以为选中的草稿工作流明确输入名称另存，不覆盖替换对象或同批其他模板。
- **存档与并发**：`forge/spec.json` 同次原子保存草稿、revision 和以草稿工作流稳定 ID 为键的模板绑定。绑定记录模板 ID、定义实例 ID 以及反投影或最近一次成功写回时的作者态指纹。若编辑器已改名、增删阶段或修改 Forge 会覆盖的节点、分组或边，旧草稿不得原位写回；可显式另存，或从当前模板新开会话。保留节点的执行槽、模型绑定和模板轮数/尝试上限按当前模板保留，不因这些手工修改报冲突；显式删除阶段则一并移除其绑定。模型和卡片增量在项目/任务写锁内重读合并，整份提交必须携带读到的草稿 revision。每成功保存一条才推进该目标的指纹和草稿 revision。旧裸草稿或仅有实例 ID、没有指纹的绑定可读取，但不能据此覆盖模板，须对选中的工作流显式另存；旧裸草稿的角色 ID 不授权写入。打开旧档不会改写原始文件。
- **自动修正**：编译未通过时，后端返回全部结构化错误与按轮次渲染的修正提示词（首行是用户可见的进行态提示，其余在可折叠的隐藏区段内）。铸造预览 Tab 把提示词经对话栏发出，等这一轮收口后重新编译，最多 3 轮；仍不通过、修正轮被停止/失败/没有带来增量/增量格式有误未应用、或模型把问题写回 `openQuestions` 时停止，说明原因并带着未解决的问题回到用户对话。
- **轮次收口事件**：生成会话用 `forge-turn-settled` 通知本轮已结束，携带 ACP prompt ID、终局、是否写入增量及未应用原因。只从身份匹配且完整的已完成回复提取增量；失败、取消、归属不明或超出读取预算都不修改草稿。读取复用时间线索引，不扫描所有历史：提示/回复正文合计与尾部读取各限 512 KiB，索引限 8 MiB。预览匹配本次提交，允许结束通知先于提交回执；重复或其他轮次的通知不能触发再次编译。
- **固定并行**：`workflow.parallelGroups` 的每项为 `{id, branches:[{id, stages:[worker ID,…]}], maxParallel, onFailure}`。顶层 `stages` 仍是 worker 的唯一定义；组在外层顺序中的位置取首个成员，分支内顺序取各自 `stages`。增量省略 `parallelGroups` 保留原组，显式 `[]` 移除；不能无损表达的拓扑拒绝修改。生成草稿每条工作流最多 10 个 worker，这不是同时运行的槽数。分支内 `end` 结束该支而非终止整个父运行。
- **失败去向**：`retry` 是失败自环；`{"goto":"dev","continueSession":true}` 失败回跳并续接目标会话；`{"new-round":"test"}` 从指定阶段开新一轮。没有失败边等同失败即结束，原位回写不凭空新增这条边。`max_attempts` 限制首次执行之外的失败跳转次数。
- **工作流预览**：待确认问题与推荐答案在阶段图前。普通 Direct 会话头部的「生成工作流」预填新的生成对话；生成会话头部的「工作流预览」打开当前草稿，没有创建或执行的副作用。保存后可试运行第一步、查看工作流、继续调整，或在相应工作流标题旁「另存为新工作流」。健康绑定的显式副本保留源模板定义、执行槽及模型绑定，以新 ID 保存并切换草稿绑定；原件不可用时另存仅从可信草稿恢复，不读取同名替代对象。蓝图和卡片都用阶段名（有稳定 ID 时即节点 ID）区分步骤；产物键在技术细节中，不充当阶段名。蓝图成功路径的层级为开始 → 分叉 → 同层并行分支 → 汇合 → 后继 → 结束；横向和纵向保持同样的依赖顺序，失败回边不把分叉或开始误排成终点。卡片支持改失败策略；技术细节默认收起。

## 4. 入口与回路

| 入口 | 触发 | 源注入 |
|---|---|---|
| A 会话 | 普通 Direct 会话详情标题栏「生成工作流」；普通会话中支持的已完成助手消息有「从此处生成工作流」，Workflow／AUTO 只提供该消息入口。生成会话标题栏改为「工作流预览」，试运行不提供生成入口。| 标题、需求、当前所选会话分支内用户发言和助手可见答复（包括助手提出的方案和之后用户的确认）；不含工具、思考、隐藏上下文或兄弟分支。按完整 locator 和消息边界选取，受限长度/窗口产生截断提示；从此处只取所选消息之后，预填摘要与隐藏材料同源 |
| B 混合素材 | 上下文管理中从角色库、全局/项目 Skill 和 Plugin 内的资源共同勾选，允许只选角色。各标签页共用一份选择。项目素材固定所属工作空间；仅全局/内置素材时再选择挂靠项目。 | 预览只显示所选名称、来源和说明；创建生成会话时按所选 ID 和域重新取职责、步骤和已声明的素材正文。角色是只读参考，不替代工作流生成师，不把素材 ID 变成阶段执行绑定或授权。 |
| C plugin | 上下文管理页 SKILL 区「Plugin」页签勾选；按来源区分已登记的 CLI 插件与用户明确选择的 WorkBuddy 本地目录。Claude Code、CodeBuddy Code 和可解析的 WorkBuddy 包按清单列出 Skill、command 或角色正文；Codex 活动版本、Qwen Code 和 Gemini CLI 扩展列出独立 Skill。读取的是选定定义，不执行包，不代表已启用或跨宿主安装。参见[兼容性证据](../Agent插件兼容性核查.md) | 同 B |
| 修改 | 工作流模板列表"对话式修改" | 反投影 Spec 作为会话初始存档基线，并随每条消息注入 |

会话入口按来源工作空间预填并临时使用 Direct，不改用户原来的模式偏好、不代选 Agent；已有未发送内容时保留并提示处理，用户已离开来源后迟到的摘要不覆盖新草稿。会话入口和修改入口先预填、由用户发送。素材入口在项目已有明确 Direct Agent 时直接提交；没有明确选择时回到输入框，不擅自选择会产生额度消耗的 Agent。发送后角色固定 workflow-forge、`origin=forge`、隐藏材料注入首条 prompt，任务与 run 原子创建。带着铸造标记时只能在来源所属项目、以 Direct 模式发送（否则就地提示，不静默降级为普通会话）。每轮完成后 runtime 提取围栏 JSON 增量合并落档并发出轮次收口事件，预览 Tab（流程图+卡片）据此刷新。

## 5. 管理

- 生成与试运行任务直接出现在工作空间与近期会话，以 `origin` 标记；普通任务没有该来源标记。左侧主导航常驻「工作流生成历史」（`/chat/forge-history`），不需要先选择项目。页面默认汇总所有已登记工作空间的生成会话和试运行，项目和来源类型仅是可选筛选；普通会话不进入此页。每行显示所属项目，打开、改名和删除仍操作该项目中同一条任务，不复制数据或建立第二个历史库。模板仍归用户级模板库；不存在按项目限定模板可用范围的变化。手动会话名优先于草稿自动标题；改会话名不改模板名。旧数据若缺少命名来源但已有标题，保留该标题；若旧版本曾把一次手动改名错误记成自动，则不能只靠文本可靠还原当时意图，不自动猜测。旧搜索索引需核实任务实例：缺少 UUID 且正文不可读、超出迁移的单项 1 MiB 核验预算或无法确认归属时，不提供可操作的搜索命中；不会因此删除项目中的会话。两个视图投影的是同一条任务；点击任务行默认打开编号最新的顶层运行，展开运行历史不改变这个目标。并行子运行仍可在历史中单独打开。删除确认绑定 project ID、task ID 和当时的任务 UUID；持锁重验身份。无 run 的草稿仍可管理；运行中、运行状态读不到或工作区刷新未完成时，不假报删除成功，确认框保留失败原因。成功删除后同步移除相应索引，不清除同项目仅路径前缀相同的其他会话；不删除已保存的工作流模板。
- 试运行：`origin=forge-trial`，使用所属项目的标准 `start_run`。固定「开始」是 `entry` 的投影，不作为试运行步骤。串行入口仅执行首个业务节点；若入口是并行组，启动前展示分支数量及上限，执行完整首组并在汇合处停止，不执行后续汇总。两者均不改源模板。预览中的范围和试运行版本来自同一份已保存模板。点击后若定义或执行绑定已变，后端不创建任务，返回最新范围；用户必须重新确认。校验通过时，创建任务使用刚校验的同一份快照。
- 铸造模板 `source=forged`（列表主题色 tag）；分享走 multica 工单通道。
