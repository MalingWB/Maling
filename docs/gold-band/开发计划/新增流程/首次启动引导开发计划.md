## 1. 实施前结论

- 复用现有 Catalog、ACP client 与 Doctor；CLI 的已安装状态不能代替 ACP 诊断成功。
- Git 可跳过，Node/npm/npx 联合检测不可跳过；至少一个 Agent 连接及模型配置通过后才能完成。
- 第三步自动发现并诊断，只展示诊断成功且已保存的 Agent；全部成功项自动配置到 Agent 管理，无需额外添加，不限于最终选中的默认 Agent。
- 默认工作流修改落到已有 `WorkflowModelBindings`，全部内置模板统一批量提交，不改用户模板、Task 或 Run snapshot。
- 首屏与只读发现不下载包、不等待所有 Doctor；仅为已发现的底层 CLI 在受控 Doctor 中准备对应适配器，不安装未发现 Agent 的全部精选包；最终写入必须具备跨文件恢复能力。
- 当前工作区存在其他在途修改，实施时需重新检查代码事实与冲突范围，不覆盖已有工作。

## 4. 完成定义

用户在干净配置空间首次启动，允许跳过 Git，但 Node/npm/npx 未达标不能完成。第三步自动检测，仅展示诊断成功且已保存的 Agent；全部成功项自动配置到 Agent 管理，无需用户额外添加。用户选定默认 Agent 与模型后，全部当前渠道内置模板的执行 slot 完成一致绑定。中途退出保留已自动配置项，默认偏好及工作流仍待显式应用；网络失败、重复点击、并发修改和写入失败均可恢复，已有业务数据不被误改。

## 17. 2026-11-04 未验证新 major 状态区分

- 修复：`EnvironmentStatus` 增加 `unverified`；策略为 Node／npm 增加 `verifiedMajors`；由 `version_status` 统一分类：命中区间为 ready，预发布或落在已验证 major 的区间外为 unsupported，低于最小已验证 major 为 unsupported，其余新 major 为 unverified。错误码为 `setup.runtime-version-unverified`，前端状态联合类型与七个语言包同步，并补充 DOM 测试。
- 不变量：`unverified` 仍明确区别于 `ready`，不会被静默标成已验证；它只有在 Node/npm/npx 实际探针、路径一致性和 npm engines 交叉检查通过时才可作为非阻断警告继续。`unsupported`、预发布、缺失、启动失败和组合不兼容继续阻断 `runtimeReady`。新增测试固定每个 policy 区间的下界 major 必须出现在 `verifiedMajors`，防止两处数据漂移。
- 自动化验收：`cargo test -p gold-band --lib onboarding::environment::` 13 项通过（含新 major 分类与策略一致性测试）；`web/tests/onboarding.test.tsx` 38 项、`web/tests/i18n-loading.test.ts` 通过；`tsc -p web/tsconfig.build.json --noEmit` 通过。

过度设计复核：只增加一个状态枚举和一份显式 major 清单，没有新增状态机、持久字段、依赖或兼容层；分类复用既有 semver 区间判断。性能复核：每项仍是一次固定区间匹配加常数次比较，无外部调用、I/O 或额外渲染。

## 18. 2026-11-05 Node.js 未验证稳定版本不再硬阻断

- 现象：另一台机器使用 Node.js 23.11.0，实际 Node/npm/npx 与 Agent 均可运行，但引导因版本不在 `22.x`／`24.x` 验证窗口而提示不支持，存量用户无法继续。
- 根因：版本分类已经能区分 `unverified` 与真正过低／预发布的 `unsupported`，但最终 `runtimeReady` 和组合校验仍只接受 `ready`，把“未验证警告”错误投影成硬门槛；同时放开单项状态会跳过 Node 路径、版本和 npm engines 的联合校验。
- 修复：新增统一 `is_runtime_usable` 判定，`ready | unverified` 才进入 Node/npm/npx 联合校验；稳定未验证版本只有在实际探针、Node 路径／版本、npm/npx 包身份及 npm engines 均一致时才令 `runtimeReady=true`。低于最低 major、预发布、缺失、执行失败、路径不一致和 engines 不兼容保持硬阻断。前端将 `unverified` 使用 `gold-warning` token 展示，并提示“工具链兼容，可继续、优先使用已验证 LTS”。
- 红测试证据：新增 `stable_unverified_node_can_continue_when_the_actual_npm_toolchain_is_compatible`，旧实现对 Node 23.11.0 返回 `runtime_ready=false`；新增路径回归固定放开版本后仍不能绕过当时的 `node-path-mismatch`（该判据已于第 20 节删除）。前端新增 Node 23.11.0 可继续且显示警告的 DOM 测试。
- 自动化验收：`onboarding::environment::` 16 项通过；Node 23.11.0 fixture 的 onboarding DOM 测试通过；七语言 catalog contract、TypeScript 和生产构建纳入最终回归。

过度设计复核：复用既有 `EnvironmentStatus::Unverified`、探针和联合报告，不新增版本白名单、持久字段、缓存、队列或依赖；只把已有状态的消费契约改为“警告可继续”。

性能复核：仍是固定 4 项并行探测和常数次 semver／路径／engines 判断，无新增进程、扫描、网络请求或渲染订阅；未验证版本不会触发额外重测。

## 19. 2026-11-05 引导不污染 Agent 管理诊断

- 现象：引导仍展示检测未通过的 Agent；Codex、CodeBuddy 在 Agent 管理页手动诊断正常后运行引导，管理页被引导失败探测改成 unhealthy，手动重诊断才恢复，重复运行会再次复现。
- 根因：`probe_candidate` 失败时调用 `invalidate_setup_diagnostic`，把引导本轮 transient 失败持久化为全局 Doctor 快照；同时已配置 Agent 每轮都被引导重复探测，违反 Agent 管理领域唯一事实源和配置 fingerprint 生命周期边界。
- 修复：新增 `candidate_detection` 分类：已配置且 fingerprint 匹配、诊断健康时直接复用；已配置诊断缺失／失败／过期时隐藏，不启动引导 Doctor、不写失败快照；未配置候选继续真实发现与 ACP 探测，只有成功才登记和持久化。失败结果改为无文案 `unavailable` channel 事件，只清除局部 pending／selection，不渲染失败列表。
- 删除旧入口：移除 `retry_setup_agent`、程序选择 API、Repair 事件和七语言失败列表文案，避免保留与新产品边界冲突的消费路径；Agent 管理页的 Doctor 仍负责既有配置的显式重诊断。
- 红测试证据：前端不可用项隐藏测试在旧实现中显示 “Broken Agent” 和修复区；领域接口测试固定健康快照复用、失败／缺失／fingerprint 变更不复用、空配置候选仍进入探测。后端原覆盖路径的失败断言证明会把健康诊断改为 unavailable，修复后该写入路径已删除。
- 回归结果：onboarding 前端 37 项通过；`cargo test -p gold-band --lib setup_reuses_only_matching_healthy_configured_agent_diagnostics` 通过；`cargo check -p gold-band-desktop` 通过。完整桌面测试和生产构建在最终验收阶段执行。

过度设计复核：不新增持久字段、状态机、缓存、队列或依赖；以现有 canonical Agent 诊断、fingerprint、generation 与提交锁收口，删除重复探测和第二写入事实源。

性能复核：已配置 Agent 从重复外部 Doctor 改为固定 Map 查询，减少进程启动、临时目录和诊断 I/O；未配置候选仍受原有最多 4 并发及单次截止时间约束，数据规模、刷新范围和前端订阅边界不变。

## 20. 2026-11-12 Node 启动器路径误判修复

- 现象：Node.js 25.5.0 通过 `C:\Users\<user>\.local\bin\node.cmd` 启动，实际运行时位于 `D:\dev\node-v25.5.0-win-x64\node.exe`；npm／npx 与 Node 观察到同一版本和同一真实运行时，引导仍显示“Node.js 启动路径不一致”并阻止继续。
- 根因：联合校验把 Node 启动器路径与 `process.execPath` 直接比较，错误假设启动器必须是最终可执行文件。Windows `.cmd` shim、版本管理器 shim 和符号链接天然允许两者不同；该判断不是运行时身份事实，属于联合校验模型不完整。两套 Node 并存只影响最终由 PATH 选中的真实运行时；只要 node／npm／npx 实际选中同一运行时且版本、npm engines 兼容，就应通过。
- 修复：删除 `node-path-mismatch` 这一无合法触发条件的原因；保留 `executablePath` 与 `nodeExecutablePath` 的展示诊断，以 node／npm／npx 三次 `process.execPath` 相等作为 Node 安装一致性的权威判据。Agent 发现仍使用有效 PATH 和本机 ACP doctor，不按 Node 大版本猜测过滤；若 CLI 安装在另一套未进入 Gold Band 有效 PATH 的 Node 前缀中，应通过纠正 PATH 或在 Agent 管理页配置可执行文件解决。
- 修复前红测试：`node_launcher_shim_may_resolve_to_a_different_actual_runtime_path` 在旧实现中将 Node.js 25.5.0 判为 `Incompatible`，期望 `Unverified` 且 `runtimeReady=true`；修复后同一测试通过。
- 自动化验收：同一红测试修复后通过；完整 `cargo test -p gold-band --lib onboarding:: --offline -j 1` 为 39 项通过、2 项按设计忽略；`cargo fmt --all -- --check`、`cargo check -p gold-band-desktop --offline -j 1`、`web/tests/i18n-loading.test.ts` 7 项和 `web/tests/onboarding.test.tsx` 38 项通过。既有“不同真实 Node 安装必须阻断”回归继续通过。
- 删除旧语义：七语言 `environmentReasons.node-path-mismatch` 文案随无触发来源一起删除，不保留兼容分支。

过度设计复核：只修正既有联合校验，不扫描机器上的其他 Node 安装、不自动修改 PATH、不新增持久字段、依赖、缓存或兼容层；多 Node 选择继续服从用户有效 PATH。

性能复核：不新增进程、文件扫描、网络请求或渲染订阅；反而移除一次无关路径规范化与比较，探针数量、并发上限和首屏加载边界不变。

## 21. 2026-11-12 已配置 CodeBuddy 未被引导发现

- 现象：用户版本中 CodeBuddy 显示名未变化，Agent 管理页 Doctor 正常，但首次引导不展示 CodeBuddy。
- 根因：管理页只按 `available=true` 显示“正常”，引导还校验配置 fingerprint。配置或 schema 变化后，旧成功 Doctor 快照 fingerprint 与当前配置不一致；管理页仍显示正常，引导却将已配置 Agent 判为 `Unavailable` 并隐藏。两处消费同一快照的语义不一致。
- 修复：旧成功快照在投影中变为 `stale`、不可用于运行选择，并在引导中返回 `Probe`；引导复用受控 Doctor 自动重测该 Agent。成功才更新快照并发布；失败只保持本轮隐藏，绝不覆盖管理页已有诊断。
- 红测试证据：`setup_reuses_only_matching_healthy_configured_agent_diagnostics` 对 stale fingerprint 原得到 `Unavailable`、期望 `Probe`；`stale_agent_diagnostic_is_not_projected_as_healthy` 原得到 `healthy`、期望 `stale`。
- 自动化验收：两个 Rust 定点回归通过；`web/tests/agent-diagnostic-status.test.tsx` 验证用户看到“需重新诊断”，七语言 catalog contract 通过。
- 删除旧语义：不再把“曾成功但 fingerprint 不一致”的已配置 Agent 静态隐藏；也不保留管理页“正常”、引导“不可用”的双重解释。

过度设计复核：复用既有配置 fingerprint、canonical Doctor、失败不落盘和 generation 保护；仅为已配置 Agent 增加一次受控 Doctor，不扫描机器、不新增持久字段、缓存、队列或兼容层。

性能复核：正常 fingerprint 匹配项仍只做内存比较，不启动进程；只有陈旧快照进入既有最多 4 并发、有界超时的 Doctor。每个 Agent 增加一次小配置序列化哈希，不访问网络或文件系统。
