# ZCode CLI 真实验收记录（2026-11-12）

## 结论

ZCode 在 Windows x64 上使用官方桌面端内置 CLI 与社区桥接器 `0.84.1` 完成了真实 GLM 后端验收：initialize、session/new、真实工具、stop、session/list、session/load + history、显式 session/resume、session/fork、进程清理与三层 Skill 调用全部通过；桥接器在 Windows 上自动发现桌面端 CLI 与 sqlite-capable Node，无需手工 `ZCODE_BIN`/`ZCODE_NODE`。第二阶段准入条件已满足，正式 Catalog 扩展为 14 项；其余平台矩阵和统一发布回归仍按发布流程执行。

## 安装与环境适配

1. 安装包从 `Downloads` 直接启动被本机安全软件拒绝；复制到临时目录后 `/S` 静默安装成功。
2. CLI 独立运行时找不到内置 Provider 配置。已将签名包内 `resources\config\provider\zcode-builtin.json` 复制到 `resources\glm\provider\zcode-builtin.json`；桥接器自身会检查 `resources\config\provider`，不依赖该副本。
3. `0.82.3` 桥接器在 Windows 上使用 Unix `which` 探测 Node，导致真实后端无法启动（日志：`no sqlite-capable node found`）。`0.84.1` 已修复 Windows 探测并优先使用当前 Node 进程；复验时未设置任何 `ZCODE_*` 环境变量，桥接器自动使用桌面端内置 `zcode.cjs` 与 fnm Node `v22.22.3`。
4. 模型选择来自 `session/new` 的 `configOptions`，默认值为 `builtin:bigmodel-coding-plan\GLM-5.3`；直接固定 `ZCODE_MODEL=GLM-5.3` 会被后端拒绝（`Provider Registry 中不存在 Model`），不能作为产品配置方式。

## ACP 生命周期：通过

运行方式：`node scripts/acp-acceptance.mjs zcode-acp-server`（无手工 ZCODE_* 环境）

| 场景 | 结果 |
| --- | --- |
| initialize | 通过；`loadSession=true`，声明 `list/resume/fork`，未声明 `close/delete` |
| session/new | 通过；返回 `sessionId`、`modes`、`configOptions` |
| 真实工具回合 | 通过；Bash `ls` 完成，`end_turn`，输出包含 `TOOL_OK:D5H2` |
| session/list | 通过；返回含历史会话的非空列表，cwd 正确 |
| stop | 通过；活动 sleep 工具被取消，`stopReason=cancelled` |
| 断线恢复 | 通过；重启 transport 后 `session/load` 返回 `replayMeta`，恢复回合仍记得 `D5H2` |
| 显式 continue | 通过；再次重启 transport 后 `session/resume` 成功，恢复回合仍记得记忆 token |
| fork | 通过；写文件回合产生 checkpoint 后 `session/fork` 返回 `forkedSessionId`，fork 会话仍记得记忆 token |
| 进程清理 | 通过；关闭 stdin 后进程自然退出，无强制回收 |

代表性 Session：`5d3e79f3-a902-4834-b173-da6f95223ced`（2026-11-12 07:45–07:50 UTC，桥接器 0.84.1）。

注意：`session/fork` 依赖工作区 checkpoint；纯聊天回合不会生成 checkpoint，直接 fork 会返回 `Internal error`。验收驱动会先执行一次写文件回合再 fork，该行为已固化在 `scripts/acp-acceptance.mjs`。

## Skill：通过

在三个作用域各创建一个一次性探针，并在同一真实回合中要求模型按精确名称依次调用：

- 项目：`<cwd>/.agents/skills/accept-zcode-project`。
- 用户主目录：`~/.zcode/skills/accept-zcode`。
- 用户共享目录：`~/.agents/skills/accept-agents`。

三个 `skill` 工具调用均被观测到，输入分别为对应 skill 名称，最终返回 `SKILL_BOTH_OK`，`stopReason=end_turn`。该结果先后在桥接器 `0.82.3` 与 `0.84.1` 上复验通过。验收后所有探针文件与新建目录已删除，`~/.zcode/skills`、`~/.agents` 恢复为不存在。

## 剩余门槛

1. macOS / Linux / Windows aarch64 矩阵未测试，不得默认为支持；发布矩阵需逐项补齐。
2. close/delete 未由桥接器声明；生命周期清理按“关闭 stdin 后进程自然退出”验收通过，该映射需保留在方案中。
3. 桥接器为社区项目，Catalog 已按方案标记 `community-adapter` 并固定 `0.84.1` 验收边界。
4. 与 DeepSeek/Qoder 一起执行统一完整回归后再发布。
