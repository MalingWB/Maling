# 工作流生成历史：统一管理入口与本地 Windows 验收

## 入口与数据边界

从聊天模式的左侧主导航直接打开「工作流生成历史」（`/chat/forge-history`）。默认显示所有已登记工作空间的生成会话和试运行，不要求先选项目；在页内选择工作空间或类型才缩小范围。普通会话不属于这个列表。模板仍是用户级资产，此页管理的是产生或试用模板的会话。跨项目查看不改变会话归属。

打开、改名、删除使用行自己的项目、任务和任务实例身份。没有 run 的记录也可管理，不凭空创建运行。删除单条记录会从最近/工作空间等投影一起移除，不删除全局模板，也不操作另一工作空间的同号任务。普通会话的搜索和运行历史与本页各自独立，不会因打开历史页改变当前项目、默认 Agent 或用户的侧栏偏好。

## 页面布局

入口固定在聊天主导航「运行模式」之后、「更多」之前。独立页面沿用客户端的集成页头、History 图标、紧凑筛选栏和主题 token。标题/描述搜索、工作空间和记录类型筛选在窄窗自动换行；历史区单独滚动。每行以标题为主，徽标区分生成/试运行，次行标出工作空间和最近活动时间，右侧为改名和删除。无 run 显示状态，不提供无效跳转；只读模式不显示写操作。一次最多展示 30 条，不用嵌套卡片或统计大屏。筛选生效后可一键还原，删除确认再次标明来源工作空间，避免同名跨项目记录混淆。

## 本地自测与正式发布

这项功能不更改仓库的 npm 构建入口、签名或更新配置。自测只需包含本页的最新桌面 EXE，不需要生成 MSI/NSIS，也不依赖开发服务器。运行该 EXE 前确认机器上已有 WebView2 Runtime；使用两个临时工作空间验证改名和删除，不操作正式数据。

资源紧张时不要与现有任务并行运行渠道发布构建。临时本机验证工具、配置和复制出的可执行文件放在仓库外；已有历史安装包不代表包含了本页。

## 人工验收

1. 新开客户端，不选任何项目，从左侧一级导航打开「工作流生成历史」。两个已登记工作空间都有记录时应同时显示，并明确每行所属项目。
2. 选择一个工作空间、切换生成/试运行、输入标题关键词，确认过滤在加载下一页之前生效；还原「全部工作空间」，另一项目记录应重新可见。
3. 打开 A 中有运行的条目应回到 A 的顶层运行；没有 run 的草稿不假造链接。验证同号或同标题的 B 条目不会被打开或修改。
4. 用测试记录改名并刷新；删除先取消，确认仍在，再确认删除。核对最近会话与工作空间同步，B 的同号任务和全局模板保持不变。Plugin/Skill 同步逻辑不在本次改动中。
