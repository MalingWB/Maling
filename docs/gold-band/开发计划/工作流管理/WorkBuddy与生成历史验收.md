### 生成历史验证结果

- **公开 App / SQLite**：旧版生产库上用隔离项目实际创建并改名，复现 `titleAutoGenerated` 仍为 `true`，按新草稿名搜索也返回空。修复后独立目标 `tests/generation_history.rs` 两例通过：自动名进入搜索；显式改名后修改草稿、重建 App、重新打开 SQLite，手工名仍有效且模板名不变。旧 UUID 的改名被拒绝。两个项目含同号任务，九条普通会话之前的生成与试运行任务在历史第一页、第二页各出现一次，另一项目的历史没有混入。
- **查询计划**：在内存 SQLite 中生成两个项目共 12,000 条合成摘要，使用生产查询的排序表达式和来源条件。添加部分索引前为 `SCAN tasks` 加临时排序，之后为 `SEARCH tasks USING INDEX tasks_generation_page`，无临时排序。来源在 LIMIT 之前过滤，列表读任务摘要和导航字段，不读草稿或聊天正文。
- **旧索引及历史标题**：最终 SQLite 专项 13/13（含 v6 实库升级、损坏记录不阻塞其他条目及恢复后重试，以及只有正文归属已验证才发布 UUID）。后台每批 64 个定位符；旧需求不可读或超过 1 MiB 核验预算时，不把旧片段冒认为新任务正文。旧数据只依据持久化事实区分自动与手工；没有归属标记但已有标题时保留原名。旧版本若把一次手工改名错误记成自动，不能据标题文字还原用户意图。可导航的搜索结果另外核验任务 UUID，不能把旧正文关联到同号新实例；无法证明归属的项仍可在工作空间查看，不把它当作已验证的搜索命中。
- **Tauri 搜索与导航**：隔离 HOME 的已注册 IPC 验证同 ID、同标题、同来源但 UUID 不同的旧匹配正文不会进入新实例，全局及本项目搜索都不返回该命中。`conversation_search_scopes_registered_roots_and_navigates_to_root_or_no_run`、`task_row_selects_latest_top_level_run` 各 1/1；默认打开最近顶层 run，而不是后出现的子运行，无 run 记录仍可定位到任务行。未启动真实 Agent。
- **真实渲染、模拟数据**：前端专项及相邻测试 144/144，通过生产类型检查。双项目浏览器夹具验证首屏外记录、生成/试运行标记、筛选及搜索、无运行记录行定位、取消删除零调用和确认删除后的重载。正常宽度、窄窗、恢复宽窗及明暗主题截图在 `target/verify/history-ui/`。这是浏览器夹具，不是已安装客户端或真实账户数据；原生删除矩阵由删除入口另行签收。

**交付门槛**：记录本次冻结后的前端构建和测试、Rust/Tauri 公共入口测试、浏览器实际操作、离线 Windows MSI/NSIS 的解包与哈希。真实 WorkBuddy 登录、真实插件执行、在用户账号安装启动不因模拟测试而标作已完成。全程不提交或推送。

**历史界面二次复核**：在 510px 窄窗中，搜索可揭示并聚焦无运行记录的真实任务行，删除仍走原确认框（[截图](../../../../target/verify/history-ui/compact-result.png)）；有运行记录的普通搜索结果不改写手动收栏偏好。开启历史筛选隐藏一个未置顶普通会话时，已打开的会话仍保留手工标题、常驻标记并收到 `paused → completed` 更新。相关页面/投影关键用例 52/52，生产类型检查通过；浏览器使用合成数据。

## 增量验收：解释 Skill 的导入限制

只验证「为什么不能导入」，不增加支持格式。使用临时或合成素材，不从用户真实登记推断拦截原因。

| 输入 | 预期可见行为 |
|---|---|
| 含顶层 `scripts/` 目录 | 对应行说明目录不受支持，不声称已检查里面的脚本。 |
| 含 `assets/logo.png` | 对应行说明该附件类型不支持；不显示本机用户目录。 |
| 文件或包超过上限／检查无法完成 | 显示实际限制；未知、不可读与不支持格式不混为一谈。 |
| 含可复制文档的 Skill 与前述受限条目并列 | 合法条目仍可导入；受限条目不可导入，但生成入口仍可选择其定义。 |

修复前在实际 `PluginForgeAssets` 浏览器组件内注入两种不同的合成限制，两行均只显示「仍可读取定义，但不支持导入此 Skill 包。」；同一页面内可导入文档包有「导入 Skill」按钮。这是前端展示复现，不是对某个本机包的诊断。

修复后在同一个浏览器夹具内，目录样例显示「包含不支持的目录」与 `scripts`，长 PNG 附件样例显示「包含不支持的文件类型」与包内相对路径，两项仍有生成复选框，第三项仍有「导入 Skill」。Plugin、生成来源与七语言相关 Vitest 4 个文件 48 项通过；后续日语和西语措辞微调后另核 7 种语言各 15 条诊断的键和占位符，一致。

宽 → 窄 → 宽（1,000 → 360 → 1,000 px）实测页面与三条素材行均无横向溢出，长附件名可换行，点击受限行的复选框后状态变为已选。浏览器运行的是当前组件与合成 IPC，未启动真实桌面客户端。

后端先经公共接口复现：不可导入条目的序列化原因是 `null`；同一测试修后得到 `unsupported-directory` 和 `scripts`。Windows 合成安装的自动发现与手选入口也测得实际目录 `tools`，拒绝导入但定义仍可按原 ID 读取。单线程生产插件模块切片共 21 项通过（App/存储引导为测试替身），不是全量 Cargo 测试。本轮生产前端构建未启动：当时可用物理内存 1,350 MiB、系统提交余量 1,727 MiB，未达到本机重型构建门槛。未打包或替换 EXE。
