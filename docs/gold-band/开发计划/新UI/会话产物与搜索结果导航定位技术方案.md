# 会话产物查看与搜索结果侧栏定位技术方案

> 状态：已在 `codex/conversation-artifact-search-navigation` 实现搜索后的会话行定位，并复用现有右侧产物 Tab。相关前端测试、生产构建和浏览器夹具验证已通过；真实 EXE 与真实数据端到端验证尚未执行。
> 分析日期：2026-10-27。

## 1. 问题与范围

1. **产物查看**：用户点击会话中的产物，直接在右侧工作区打开独立 Tab 查看内容；同一产物已打开时激活已有 Tab。2026-10-27 用户确认以此满足需求。
2. **搜索结果侧栏定位**：用户选择搜索结果后，现有流程已能打开对应会话；还需要左侧栏展开所属工作区、选中对应会话行，并将该行滚动到可见位置。定位到会话行即可，不需要展开或定位运行记录。

本方案不改变搜索匹配或搜索结果排序，不设计会话正文内的关键词定位。产物侧不包含运行目录树定位、目录根范围调整或新增系统文件管理器入口；搜索侧只补齐会话行的侧栏定位，不增加运行历史展开或 Run 定位。

## 2. 当前证据与验证边界

### 2.1 产物预览

- `web/src/components/acp/ACPChatDialog.tsx` 的 `openArtifact` 以 attempt locator 和产物名称创建 `conversation-asset` 资源。
- `web/src/components/workspace/files/ConversationAssetWorkspacePanel.tsx` 已按资源携带的 locator 和名称调用现有产物读取接口，并在右侧工作区展示内容与加载/失败状态。
- `web/src/components/workspace/right-workspace-context.tsx` 已提供 `conversation-asset` 资源 key 和按 key 打开或激活 Tab 的能力。
- 普通节点与动态节点的实际文件路径继续由后端现有产物读取能力解析。

**判断**：现有实现已有“点击产物 → 右侧工作区 Tab 查看”的主链路。原方案将产物查看扩大为运行目录树揭示，超出了用户确认的需求；应收敛为复用现有能力，并验证来源身份、Tab 复用与异步读取隔离。

### 2.2 搜索结果

- `web/src/components/conversation/ConversationSearchDialog.tsx` 选择结果后回调上层。
- `web/src/lib/conversation-search.ts` 已把搜索结果映射为现有会话页面 locator；其中的 Task/Run 字段由既有会话打开流程消费。
- `web/src/App.tsx` 已通过 `onSelectConversation` 统一打开目标会话，无须先从侧栏任务页反查搜索结果。
- `web/src/components/conversation/ConversationSidebar.tsx` 原有工作区展开请求、当前会话身份和行选中态；本次补齐搜索后的工作区展开、会话行选中和一次滚动，并阻止该路径自动请求 Run 历史。
- `web/src/lib/conversation-sidebar-loading.ts` 的普通会话页为 24 项，合并窗口上限为 120 项。目标可能尚未加载；单纯查找 DOM 并滚动不能覆盖该情况，普通追加后裁剪也可能丢掉旧目标。

**判断**：这是已有会话导航的侧栏联动实现不完善，应复用现有导航并补齐所属工作区展开、会话行选中与滚动。定位止于会话行，无须进一步展开和定位 Run 记录。侧栏数据未就绪不能阻塞会话打开。

### 2.3 实施证据与验证边界

“搜索已打开会话但侧栏未定位”来自用户对当前效果的明确说明。实施中先建立失败测试，实际观察到搜索附带请求 Run 历史、重复选择不再次滚动、侧栏重挂载重放已消费定位，以及实时插入会话使列表超过 120 + 1 行；修复后使用相同测试确认通过。

已启动实际前端，在浏览器中以可控 API 夹具验证跨工作区、未加载目标、120 行窗口外目标、重复选择、侧栏收放，以及点击同一会话保留目标行、切换其他会话清理目标行。该验证使用真实 App 与侧栏组件，但不等同于真实 EXE、真实工作区或真实产物文件的端到端验证。

## 3. 设计原则与权威数据

- **产物身份**：沿用 `conversation-asset` 的完整来源 locator、既有 canonical `taskUuid` 与产物名称。打开的 Tab 固定读取该资源来源；当前选中分支不是产物来源的替代事实源。
- **会话导航**：搜索直接使用结果已有的定位信息进入统一会话导航；内部 Task/Run 映射和打开会话接口沿用现有流程。身份校验与迟到请求隔离继续复用已有边界，不新建身份体系；未加载侧栏行的读取边界见 5.2。
- **导航状态**：产物查看复用当前会话作用域下的工作区 Tab 生命周期；搜索选择在现有页面导航事务中同时提交一次侧栏定位意图，包含目标身份与现有请求序号。行选中态继续由当前页面和列表作用域派生，不另存一份“当前会话”。
- **触发边界**：由用户点击产物或选择搜索结果发起操作；同一会话再次被搜索选中时可重新定位。定位完成后消费本次意图；后台刷新、重命名和身份补全不得重新滚动，迟到请求不得覆盖更新的用户选择。
- 复用现有工作区、产物查看器、搜索、会话导航和 UI 组件，不新增依赖、基础控件或假设性缓存。

## 4. 产物在右侧工作区查看

### 4.1 行为契约

1. 点击产物后，直接打开右侧工作区并创建该产物的只读查看 Tab；相同产物再次点击时激活已有 Tab。
2. 不同来源的同名产物使用不同资源 key，可分别打开、切换和关闭。Tab 标题沿用产物名称，内容复用现有查看器。
3. 产物 Tab 使用打开时的来源 locator；在同一会话内切换执行分支后，仍可查看已打开的产物。
4. 先打开并激活 Tab，再加载内容；加载与失败状态显示在该 Tab 内。快速切换不同产物时，旧请求不得覆盖当前内容。

### 4.2 数据与接口

- 沿用 `ConversationAssetWorkspaceResource`、`conversationAssetWorkspaceResourceKey`、`openResource` 与 `ConversationAssetWorkspacePanel`。
- 沿用 `showArtifact` 读取普通节点和动态节点的产物；前端只传现有来源 locator 和产物名称，由后端解析文件路径。
- 仅激活的产物 Tab 请求并展示内容；继续使用现有会话作用域、资源管理与异步请求隔离机制。
- 本需求不新增产物定位接口、目录揭示意图、目录跟随/固定模式或新的文件身份。

## 5. 搜索打开会话后同步定位左侧会话行

### 5.1 行为契约

1. 用户选择搜索结果后关闭搜索弹窗，通过现有统一导航打开对应会话，同时发起本次侧栏定位。
2. 左侧栏展开目标所属工作区，使用工作区列表作用域选中对应会话行；即使该会话也在置顶区，搜索定位仍以所属工作区下的会话行为目标。
3. 目标行完成渲染后，在现有侧栏滚动容器中将其滚动到可见位置；已经可见时不移动。保持其他工作区的展开状态，不修改最近活跃工作区、会话活动时间或排序。
4. 目标尚未加载时，补齐目标的轻量行数据后完成定位；会话内容先按现有流程打开，不能等待侧栏加载。
5. 定位止于会话行，不要求展开运行历史、选择 Run 或加载其历史页。现有依赖页面变化自动展开运行记录的逻辑需要核对，不能让搜索定位附带触发该操作。
6. 连续选择时只有最新意图可提交和滚动；用户中途切换、手动收起目标工作区或主动滚动后，取消尚未完成的自动定位，避免迟到请求抢回位置。目标不可用时按现有错误机制反馈，不定位到其他会话。

### 5.2 数据与接口

- 复用 `searchConversationTasks`、`conversationPageForSearchResult` 和 `onSelectConversation` 打开会话；扩展现有工作区展开请求以表达本次目标会话行，复用统一导航的请求隔离机制，不建立独立导航状态机。
- 使用既有 `projectId`、`taskId` 与可用的 canonical `taskUuid` 匹配会话；名称不参与身份判断。侧栏定点摘要与页面身份补全使用同一套既有身份校验，不新建跨层 identity。
- 目标已在工作区列表中时直接复用该行，不为定位额外读取摘要。未加载时按目标身份读取一个 `ConversationTaskRowVm` 轻量摘要，优先复用现有行投影能力；若缺少只读入口，补充单行摘要读取接口，而不是逐页追到目标。
- 普通分页窗口与 cursor 保持原有语义。当前导航最多额外保留一个定位目标的行投影，按既有身份去重并按活动时间顺序展示；目标已经进入普通页时复用普通行。权威 `lastActivityAt` 前进时，目标由临时投影原子转为普通行：清除 `locatedTask`、按最新活动排序并裁剪回 120 行，避免后续离开会话时把已重新活跃的目标当作临时行删除。重命名、状态更新或活动时间未前进时保持 120 + 1 投影。不要把目标送入普通追加裁剪后丢弃，也不要强插到列表首位改变排序。
- 额外目标行沿用既有行类型，只用于本次会话导航的侧栏呈现；离开当前会话或目标被删除时清理，同一会话内导航保留，普通页最多 120 行加目标最多 1 行，不持久化、不积累多个历史目标。活动事件、终态事件和任务快照都通过同一晋升规则维护该边界。行上的重命名、删除和状态更新继续走现有统一数据更新入口。
- 实现只在既有 `ConversationSidebarVm` 增加瞬时 `locatedTask` 身份引用，行数据仍存放于 `tasksByWorkspace`；普通页合并和实时快照写入都维护 120 + 1 上限。目标进入普通页后清除额外引用，保留同一普通行。
- 定点读取只消费该行的身份、标题、模式、状态等展示字段，不读取会话正文、全部任务或运行历史，不调用包含完整 Workflow 校验的重型详情链路。耗时和错误显示在目标工作区内，不影响已打开的会话。
- 新增只读 `get_conversation_task_summary(projectId, taskId, taskUuid?)`，复用已有轻量 `conversation_task_row_vm`，校验搜索携带的 canonical UUID。该投影会枚举目标会话的 Run 目录名称以选出最新 Run，并读取该条摘要及既有未读结果索引；不读取所有 Run 正文、session tree 或完整 Workflow。

### 5.3 定位时序

选择结果时同步提交页面目标、工作区列表作用域和一次定位请求；侧栏随后展开工作区，并复用或补齐目标行。目标 DOM 就绪且请求仍有效时执行一次可见性检查，必要时只滚动侧栏的 `ScrollArea`，随后通过原请求的 `scrollHandled` 标记消费。该消费结果保留在 App 层，侧栏收放或重挂载不会再次滚动。不要监听当前会话、整个侧栏 VM 或行对象的每次变化来重复滚动，也不轮询 DOM。

## 6. 实施顺序

1. 验证现有产物 Tab 路径：首次打开、重复激活、同名不同来源、分支切换与异步读取隔离；已有行为满足约定时直接复用。

3. 在现有导航中补齐一次会话行定位；先完成已加载行的展开、选中与滚动，再补齐未加载目标的单行读取和有界投影。移除搜索路径对运行历史自动展开的依赖。
4. 使用同一失败测试确认转绿，并运行受影响接口、组件与桌面端回归；按实际改动维护结构化错误与必要的多语言界面文案。

## 7. 验收与回归测试

### 7.1 产物

- 点击产物打开右侧工作区 Tab，并显示该来源的内容；普通节点、动态节点和不同 attempt 均正确。
- 同一产物重复点击激活已有 Tab；不同来源的同名产物互不覆盖。
- 切换会话执行分支后，已打开的产物仍保留自己的来源；Tab 可正常切换与关闭。
- 首次打开立即显示加载状态；读取失败在目标 Tab 内反馈。快速切换产物时，旧响应不得覆盖新内容。
- 非激活产物 Tab 不额外请求正文，不因查看产物加载目录树或完整运行历史。

### 7.2 搜索

- 同一及跨工作区选择搜索结果后，弹窗关闭并打开正确会话，侧栏展开所属工作区、选中会话行并滚动到可见位置；目标已可见时不产生多余滚动。
- 目标工作区折叠、目标行不在视野内、目标未加载或旧于 120 行普通窗口时，仍完成会话行定位。置顶副本不干扰所属工作区行的选中和定位。
- 同一结果再次选择可重新定位；后台刷新、重命名和身份补全不重复滚动，不修改最近活跃工作区或会话排序，也不改变其他工作区展开状态。
- 连续选择、慢请求、用户中途切换或手动滚动/收起、目标删除及摘要加载失败均不出现错误会话或迟到滚动。摘要失败不清空已打开的会话，并可在目标工作区重试。
- 已加载目标不增加摘要请求；未加载目标只定点补一行，不串行加载侧栏历史页，不增加运行历史查询。重复定位不积累目标投影，普通页与定位目标相遇时不出现重复行；目标重新成为最新会话后进入普通 120 行窗口，切换到其他会话时不消失。
- 从接口层固定定点读取范围、身份、请求次数和窗口上限，再用 DOM 回归固定展开、选中、一次滚动与请求失效行为。真实 EXE 完整验证产物查看与搜索后侧栏定位两条用户路径。

## 8. 过度设计与性能评审

- **根因判断**：搜索打开会话的既有设计可复用，缺陷在导航没有完整同步侧栏展开、选中和滚动，应完善该联动。无需重构任务运行模型。
- **过度设计**：产物目录揭示与搜索 Run 定位已移出范围。仅复用现有导航请求表达一次会话行定位；额外单行投影只解决“目标不在普通 120 行窗口内仍须可见”的具体约束，不新增领域实体、持久字段、索引、缓存体系、队列或独立状态机。
- **数据与 I/O**：搜索仍沿用 300ms 防抖和最多 20 条结果；定位只处理用户选中的一个会话。已加载行零额外摘要读取，未加载行至多读取一个轻量摘要；不顺序翻完历史，不扫描所有任务或读取全部运行历史。定点接口复用既有摘要投影，其最新 Run 选择仍随目标会话的 Run 目录数量增长，并读取既有未读索引；本次没有新增全任务扫描或重型详情校验。
- **内存与渲染**：普通任务窗口最多 120 行，当前定位目标最多额外 1 行，局部去重与排序限于该有界集合；复用现有 `TaskRow` 和 `ScrollArea`，定位结束即消费滚动请求，不增加持续滚动监听或扩大流式更新订阅范围。
- **验证**：已用接口与 DOM 测试固定身份、窗口上限及一次定位行为；浏览器验证 120 行窗口外目标时，工作区呈现 121 行，定位新增摘要请求 1 次、分页请求 0 次、Run 历史请求 0 次，目标处于可视范围并选中。重复选择不增加摘要请求，侧栏收放不重放滚动。数据集合有界，没有新增持续热路径，无须额外 benchmark。

## 10. 审查缺陷修复记录（2026-10-28）

- **根因**：侧栏活动投影只更新 `lastActivityAt` 和排序，没有撤销搜索定位目标的临时身份；后续离开会话仍按临时行清理，导致重新活跃的旧会话被删除。该问题属于瞬时定位状态与普通分页窗口的生命周期转换缺失。
- **修复**：新增统一的定位目标晋升规则。活动事件、终态事件和任务快照只要观察到权威活动时间前进，就原子执行“目标置前 + 清理 `locatedTask` + 裁剪回 120 行”；未前进的活动、重命名和状态更新仍保留 120 + 1 的 transient 投影。
- **红绿验证**：先以 120 个普通会话加 1 个旧目标构造失败用例，活动 / 终态 / 快照三条路径在旧实现上均出现目标保留断言失败；修复后同一参数化用例通过，并补充活动时间未前进时仍按临时行清理的反向用例。
- **回归与构建**：`npm run web:test -- conversation-sidebar conversation-task-state right-workspace workspace-file-reference file-content-store --reporter=dot` 通过 19 个文件、158 项测试；`npm run web:build` 通过 TypeScript 与 Vite 生产构建（仅既有大 chunk 提示）。
