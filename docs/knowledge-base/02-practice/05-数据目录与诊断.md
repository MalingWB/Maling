# 数据目录与诊断

> 出问题要「看数据」的时候，知道东西在哪、哪些能删、哪些不能动非常重要。

## 1. 两条铁律

1. **项目目录只放配置覆盖**：`<repo>/.gold-band/` 只存可覆盖的项目级配置，不放任何过程数据。
2. **过程数据全部在用户目录**：task、run、session、日志、产物、附件都在 `~/.gold-band/projects/{project-id}/` 下。

所以：删掉项目里的 `.gold-band/` 不会丢历史；删掉 `~/.gold-band/` 会丢全部历史。

## 2. 用户目录结构

```text
~/.gold-band/                       # 可用 GOLD_BAND_HOME 覆盖
├─ config.json
├─ logs/
│  └─ runtime.log                   # 进程级全局日志，8 MiB × 4 份轮转
├─ desktop/
│  ├─ agent-diagnostics.json        # Doctor 健康快照（每次探测整份替换）
│  └─ agent-model-catalogs.json     # 各 Agent 已观测的模型配置（Doctor 失败不清空）
├─ doctor/acp/                      # 临时 ACP 诊断；成功删除，失败保留有界诊断包
├─ context/profiles/                # 用户级角色（Markdown）
├─ presets/workflows/               # 用户级工作流预设
├─ providers/                       # provider 相关
├─ skills/                          # 全局 SKILL
└─ projects/
   └─ {project-id}/                 # 由仓库路径生成的稳定 id
      ├─ project.json               # 仓库路径与 project id（可重建的低频 manifest）
      ├─ tasks/
      │  └─ task-001/
      └─ scheduled-tasks/
         └─ scheduled-task-001/
```

`project-id` 的格式是 `{可读 slug}--{8 位 BLAKE3}`（例如 `d-projects-example-app--3d4964d2`），由**规范化仓库路径**确定性生成。Windows 下不区分盘符 / 路径大小写。

## 3. 单个 task 里有什么

```text
tasks/task-001/
├─ authoring/
│  ├─ conversation.json      # 会话元数据（标题、lastActivityAt、resident 等）
│  ├─ inputs/                # 初始附件（绑定 task，重跑复用）
│  ├─ auto.json              # AUTO 的「下一次 Run」配置
│  └─ workflow.json          # 工作流的「下一次 Run」配置
├─ runs/
│  └─ run-001/
│     ├─ run.json            # run 级生命周期与终局
│     ├─ workflow.snapshot.json   # 本 run 冻结的工作流快照
│     ├─ rounds/
│     │  └─ round-001/
│     │     ├─ round.json
│     │     ├─ events.jsonl
│     │     └─ nodes/<node-id>/attempt-001/
│     │        ├─ node.json          # attempt 级状态与 outcome
│     │        ├─ acp.raw.jsonl      # 完整 ACP 收发帧
│     │        ├─ acp.diagnostics.jsonl
│     │        ├─ worker-ref.json    # 会话继续所需的引用
│     │        ├─ artifact-emission.json   # 产物发射阶段（business-turn / finalizing）
│     │        ├─ user-inputs/       # 追问附件
│     │        └─ dynamic/           # AI-DYNAMIC 内部状态（如有）
```

### AI-DYNAMIC 的内部状态

```text
attempt-001/dynamic/
├─ dynamic-run.json
├─ allowed-workflow-snapshots.json
├─ graph.json
├─ events.jsonl
├─ nodes/<internal-node>/attempt-001/
├─ groups/<group-id>.json
└─ proposals/<proposal-id>.json
```

**外层 `node.json` 只记录 AI-DYNAMIC 节点的最终生命周期**，内部图不会污染外层 round trace。

## 4. 哪些能删、哪些不能删

| 对象 | 能不能删 | 后果 |
| --- | --- | --- |
| `<repo>/.gold-band/` | 可以 | 丢项目级配置覆盖，不丢历史 |
| `projects/{id}/tasks/task-xxx/` | 可以（推荐用界面删除） | 丢该会话全部历史；界面删除会尽量移入回收站 |
| `logs/runtime.log*` | 可以 | 丢日志，不影响业务 |
| `desktop/agent-diagnostics.json` | 可以 | 下次启动重新诊断 |
| `desktop/agent-model-catalogs.json` | 可以 | 会丢失已观测的模型配置，需重新「获取模型配置」 |
| `doctor/acp/` | 可以 | 只是临时诊断 |
| `projects/` 整个目录 | **不建议** | 全部历史、产物、会话引用丢失 |
| `core.db` | **不要手删** | 会话索引、定时任务、IM 待投递记录会丢 |

> 手动改状态文件风险很高：`run.json` / `node.json` 是 canonical state，写错会让 run 无法恢复。

## 5. 日志与诊断

### 5.1 日志在哪

- 统一在 `~/.gold-band/logs/runtime.log`，进程级单一异步 writer，8 MiB × 4 份轮转。
- 桌面端启动时就会预创建该文件，即使还没选工作空间。
- 默认 Info 级别；在设置 → 高级里开「记录详细日志」可得到 DEBUG 细节。

**日志里不会出现**：prompt 正文、文件内容、命令参数、路径、remote URL、Token。

### 5.2 需要的几类诊断

| 诊断 | 位置 / 开关 | 用途 |
| --- | --- | --- |
| ACP 原始帧 | 会话页「原始帧」面板 | 看 Agent 到底收发了什么 |
| ACP diagnostics | `attempt-xxx/acp.diagnostics.jsonl` | adapter 复用、JSON-RPC 耗时 |
| AI-DYNAMIC 事件 | `dynamic/events.jsonl` | 拆分调度、worktree 创建、prompt 构建耗时 |
| 源码管理加载诊断 | 设置开详细日志 + `gold-band::git::load` | Git 加载慢在哪一步 |
| 工作区布局诊断 | `localStorage.setItem('goldBand.debug.workspaceLayout','1')` 后刷新；`Ctrl+Alt+Shift+L` 导出 JSON | 三栏布局 / 收起展开异常 |
| 前端致命错误 | 自动经 `report_frontend_error` 写入 runtime.log | 页面白屏 / 崩溃 |
| npx 缓存修复 | Agent 管理卡片 | 内置 Agent 起不来 |

### 5.3 排查顺序建议

```text
1. 看会话页：状态点、pause reason、错误横幅的文案与错误码
2. 看原始帧：最后一条 outbound 有没有对应 inbound
3. 看 acp.diagnostics.jsonl / dynamic/events.jsonl：卡在调度、worktree 还是 provider 首响应
4. 看 runtime.log：结构化 ERROR
5. 还不够 → 帮助 → 用户反馈，附带关联会话 + 日志
```

## 6. 用户反馈附什么

「帮助 → 用户反馈」可提交：

| 字段 | 约束 |
| --- | --- |
| 问题描述 | 必填，1–2000 字符 |
| 关联会话 | 可选，从已注册工作空间的任务里单选 |
| 截图 | 可选，0–4 张；PNG/JPEG/WebP；单张输出 ≤ 5 MiB |
| 上传日志 | 默认开启，只上传运行日志**尾部 512 KiB** |
