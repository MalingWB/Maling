# 能力全景

> 这一篇是「能力清单」：MALING 到底有哪些功能模块，各自负责什么，入口在哪里。
> 想直接上手，跳 [快速上手](../02-practice/01-快速上手.md)。

## 1. 一览表

| 能力域 | 关键能力 | 主要入口 |
| --- | --- | --- |
| **会话与编排** | Direct 对话、Workflow 工作流、AUTO 动态编排、会话队列、停止/继续、重跑 | 会话主页 composer、会话运行页 |
| **Agent 管理** | 内置 11 个 ACP Agent + 自定义 Agent、环境诊断、模型目录获取、npx 缓存修复 | 侧栏「Agent」 |
| **上下文管理** | 角色（Profile）、MCP 服务、SKILL 三类可复用资源 | 侧栏「上下文」 |
| **运行模式管理** | 按项目管理工作流模板与 AUTO 配置 | 侧栏「运行模式」 |
| **右侧工作区** | 文件浏览/编辑、源码管理（Git/GitHub）、内置浏览器、运行产物目录 | 会话页右侧栏 |
| **自动化** | 定时任务（单次/重复/Cron）、保持系统唤醒、完成通知 | 侧栏「更多 → 定时任务」 |
| **远程协作** | 企业微信 / 飞书机器人远程干预与信息通知 | 设置 → 通用 → IM 远程干预 |
| **需求接入** | Multica 需求列表接入、领取并执行 | 侧栏「更多 → 需求管理」 |
| **个性化** | 主题、明暗、字体、壁纸、头像、个人数据分析 | 设置、帮助菜单 |
| **可观测性** | 系统提示、原始帧、产物、附件、token 与耗时、诊断日志 | 会话运行页、右侧工作区 |
| **脚本化 / CI** | headless CLI 执行与继续 | 命令行 `gold-band run / continue` |

## 2. 会话与编排

### 2.1 三种运行模式
Direct / Workflow / AUTO，行为差异见 [运行模式指南](../02-practice/02-运行模式指南.md)。

### 2.2 会话内的关键动作

| 动作 | 说明 |
| --- | --- |
| 发送 / 排队 | 运行中仍可继续输入，形成「待发送」队列，按顺序被消费 |
| 停止 | 停止当前 ACP 回合。Direct 停止后可以继续普通对话；Workflow/AUTO 停止后进入可恢复暂停 |
| 继续工作流 | 仅 Workflow/AUTO 的可恢复暂停出现；恢复当前节点的 runtime 控制 |
| 恢复工作流 | 当前节点已完成但转换中断时出现；从已持久化结果直接做下一步决策，不重新调用 Agent |
| 继续并发送 | 有输入时把「用户输入 + 恢复意图」原子提交，避免先普通发送再 continue |
| 重跑该任务 | 用同一需求开一个**新 run**；若当前 run 还在跑，会先停止 |
| 常驻会话 | Direct 专用；防止空闲回收，适合挂着定时任务等长时间工作 |
| 会话切换 / 搜索 | 会话标题处切换 session；`Ctrl+F`（macOS 也支持 `Cmd+F`）全局搜索会话 |

### 2.3 干预与确认

- **权限请求**：Agent 要求执行命令、写文件等时弹出权限卡，可 Allow / Reject（部分权限模式可加「Auto Accept」）。
- **用户追问（Elicitation）**：Agent 需要补充信息时以结构化表单提问，支持单选 / 多选 / 自定义答案 / 分步。
- **人工 check**：`manual_check` 节点暂停，由你点「成功」或「失败」决定走向。
- **系统通知**：人工确认、权限请求、执行错误、进程中断四类暂停会发系统级通知，点击可 deep link 回对应节点。

## 3. Agent 管理

- **内置 Agent 目录（11 个）**：Claude（`claude-acp`）、Codex（`codex-acp`）、Cursor、Gemini、CodeBuddy、Goose、Qwen Code、OpenCode、Kimi Code、Amp、Pi。
- **自定义 Agent**：任何 ACP-compatible Agent 都可以手动添加，需要填稳定 Agent ID 与启动配置。
- **诊断（Doctor）**：检查 Agent 能否启动、ACP 能力、可用模型目录、MCP transport 支持情况。
- **模型目录**：「获取模型配置」按模型抓取可选配置项（思考强度、context 等），供 composer 与工作流 Inspector 使用。
- **npx 缓存修复**：内置 Agent 通过 npx 分发，缓存损坏时可一键清理并重新诊断。

> 内置 Agent 的命令与参数由客户端内嵌 Catalog 维护，升级客户端后自动更新；自定义 Agent 的配置完全由用户维护。

## 4. 上下文管理（三类可复用资源）

| 资源 | 作用 | 存储 |
| --- | --- | --- |
| **角色（Profile）** | 可复用的执行身份 / 指令集，工作流节点通过稳定 `profile id` 引用 | 内置 + 用户级 Markdown |
| **MCP** | 给 Agent 挂工具服务（stdio / HTTP，含 OAuth） | 配置 + 诊断状态 |
| **SKILL** | 给 Agent 的技能包（`SKILL.md`），可全局或项目级 | `.gold-band/skills/` 或 Agent 原生 skills 目录 |

要点：
- 角色支持**文件夹批量导入**（Markdown，最多 5000 个文件），可兼容 `name/title`、`summary/description`。
- 角色支持**动态模板**：使用时按当前执行上下文渲染正文。
- 内置角色不可直接覆盖保存，只能另存为自定义角色。
- SKILL 同名可并列展示（按实例目录识别），同步到某个 Agent 时若目标已有同名原生 skill 会直接阻止并提示冲突。
- MCP 采用**先保存 → 再验证**策略；状态灯：🟢 健康 / 🟡 需要授权 / 🔴 不可用 / ⚪ 未检查。健康检查只在保存、重新启用、手动诊断时触发，不批量扫。

## 5. 右侧工作区

右侧工作区不是"杂项栏"，而是按资源类型分 Tab 的当前会话辅助区。

| 资源 | 能力 | 说明 |
| --- | --- | --- |
| **工作空间** | 文件树浏览、搜索、新建 / 重命名 / 删除、编辑、图片 / Markdown / SVG / HTML 预览 | 只读写当前项目或 linked worktree；删除一律进回收站，`Ctrl/Cmd+Z` 可撤销 |
| **源码管理** | 更改列表、Stage/Unstage、Commit、分支 / 标签 / Worktree、Fetch/Pull/Push/Stash、提交历史与 Diff、GitHub PR/Issue | 图形化 Git，不暴露终端命令 |
| **内置浏览器** | `http(s)` 与本地 HTML，多页签、前进后退、地址栏搜索（百度 / Google / Bing）、电脑版 / 移动版切换 | 零权限子 WebView，登录态跨重启保留 |
| **运行目录** | 查看当前 attempt 的产物（只读） | 随选中 attempt 原位切换，不新增 Tab |
| **附件 / Diff / 压缩摘要** | 按需打开的历史资源 | 固定其原始 locator，不随尝试切换而重绑 |

## 6. 自动化：定时任务

- **定位**：定时任务是**触发层**，不是第四种运行模式。它触发 Direct / Workflow / AUTO，产物仍然是 `task → run → round → attempt`。
- **调度类型**：单次、重复（每小时 / 每天 / 工作日 / 每周 / 每隔 N 分钟或小时）、Cron。
- **两种会话策略**：`new`（每次新会话）/ `continuous`（同一 ACP 会话持续追问，仅 Direct）。
- **立即执行**：不改变原计划的下一次执行时间。
- **全局运行设置**（设置页）：保持系统唤醒、完成通知、执行记录保留天数（1–3650 天，默认 30）。

## 7. 远程协作：IM 远程干预

在桌面客户端内直连**你自己的**企业微信 / 飞书机器人：

- 工作流进入权限审批、用户追问、人工 check 等待态时，把交互卡片推送到 IM；
- 你在手机上点按钮即可完成同意 / 拒绝 / 回答 / 成功判定；
- 任一端处理成功后，桌面端与另一端收敛到同一终态（只有「先到」的那次会写处理结果）；
- 也可按类别开启 Run / ACP turn 的信息类通知。

**边界**：只支持交互卡片的明确控件，不做自然语言 ChatOps；不支持群聊；不支持通过 IM 启停 / 重跑 / 编辑工作流；不提供云端中转网关。

## 8. 需求接入：Multica

- 客户端扮演 Multica 的 **Daemon** 角色：拉取任务、在本地执行、回传结果。
- 在「需求管理」里连接服务端、绑定工作空间，然后把需求「执行」或「取消」。

## 9. 个性化与分析

| 项 | 说明 |
| --- | --- |
| **主题** | Gold Band 主题（默认）、技术中性；浅色 / 深色 / 跟随系统 独立设置 |
| **字体** | 界面 UI 与编辑器分开配置，可用内置 Inter + MiSans / JetBrains Mono，也可自选本机字体栈（最多 16 项），字号可调 |
| **壁纸** | 浅色 / 深色分别配置，支持导入（PNG/JPEG/WebP）、最近使用、可见度 20%–100% |
| **头像** | 你与各 Agent 的头像，支持上传裁剪与最近使用 |
| **更新日志** | 帮助 → 更新日志，随安装包内置当前版本七语言说明 |
| **个人数据分析** | 帮助 → 个人数据分析：基于本地 SQLite 索引生成确定性报告（用量、效率、Token、上下文等），可选 Agent 生成洞察 |

## 10. 可观测性

会话运行页能看到的「事实」分四层，**不要用下层推断上层**：

```text
canonical state   （task / run / round / node 的最终事实）   ← 唯一权威
observability     （events / logs / raw stream）
artifacts         （runtime 规范化产物）
attachments       （provider 或节点产生的附件）
```

在界面上对应：

- **系统提示**：本次会话实际注入的 system prompt；
- **原始帧**：ACP JSON-RPC 收发帧，可搜索、过滤、分页；
- **产物** / **附件**：规范化产物与 Agent 产生的文件；
- **用量与耗时**：token、单轮耗时、压缩状态等。

## 11. 脚本化 / CI

`gold-band run` / `gold-band continue` 是无人值守 headless runner：

- 在当前 Git 仓库里按 AUTO 或指定工作流执行一次需求；
- stdout 输出 canonical `RunState`，用退出码表达结果（0 成功 / 1 完成但非成功 / 2 暂停 / 3 命令失败 / 4 仍运行）；
- 无人应答时：追问自动 `decline`，权限自动 `cancelled`，暂停类节点保持暂停。

详细用法见 [架构与扩展点](../03-reference/01-架构与扩展点.md#7-cli-入口)。
