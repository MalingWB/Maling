# 常见问题 FAQ

> 按"我被问到最多的顺序"排列。答案尽量短，细节指向对应章节。

## A. 定位与选型

### A1. 它和 Coding Agent 内部的工作流有什么区别？

Agent 内部的工作流通常是"主 Agent 调度子 Agent"或"脚本调度 Agent"，编排的是**会话**。
MALING 编排的是 **harness**：每个节点可以是完全不同的 Agent（不同架构、不同工具集）。所以你能用"带浏览器能力的 Codex"做验收节点，用"轻快的 Pi"做开发节点——差异是整个 harness，不只是上下文。

### A2. 它和 Codex App 这类 Agent 客户端有什么区别？

那些客户端围绕**一个固定 Agent** 构建。MALING 在 Agent 之上，可以切换、组合不同架构的 Agent 并继承它们各自的能力。
代价是：MALING 触不到 Agent 内部循环，所以"在 Agent 循环中途用提示词转向"这类功能更难做。

### A3. 它和其他 ACP 客户端有什么区别？

MALING 从工作流起家，ACP 客户端能力是在此之上补齐的。差别在于：
- 验收标准、前序上下文摘要、停止与恢复、AUTO 的节点合并；
- runtime 真正驱动节点推进与失败处理，Agent 只需专注当前节点。

### A4. 该用 Direct 还是工作流还是 AUTO？

见 [运行模式指南 §5 选型速查](../02-practice/02-运行模式指南.md#5-选型速查)。
一句话：想聊 → Direct；知道步骤 → 工作流；不知道怎么拆 → AUTO。

### A5. 我用哪些 Agent 比较好？

内置 11 个：Claude Code、Codex、Cursor、Gemini CLI、CodeBuddy、Goose、Qwen Code、OpenCode、Kimi Code、Amp、Pi。
推荐起点是 **Claude Code 或 Codex**（能力完整、社区验证多）。其余取决于你本机环境和该 Agent 的 ACP 支持度。

## B. 上手与配置

### B1. 为什么模型 / 权限下拉是空的，或显示"尚未获取此模型的配置"？

两个原因：
1. Agent 还没诊断通过 → 去 Agent 管理点「诊断」。
2. 该模型还没被抓取过配置 → 点「获取模型配置」。

注意：Doctor 失败**不会**清掉已经抓到的模型配置；只有切换 Agent（配置重置）才会清空。

### B2. 为什么"使用本地 Claude"开关打开后启动失败？

该开关只负责给 ACP adapter 注入 `CLAUDE_CODE_EXECUTABLE`，不会改 adapter 命令本身。Windows 下必须解析到原生 `claude.exe`（会读 `claude.cmd` wrapper 找到真实 exe）；解析不到就**不注入**，让 adapter 走自身 fallback。
如果开启了 `requireLocalClaudeExecutable`（默认关），解析失败会直接报错而不是 fallback——这是给排查用的严格模式。

### B3. 内置 Agent 的启动命令我能改吗？

不能。内置 Agent 的命令与参数由客户端内嵌 Catalog 维护，管理界面只读，升级客户端后自动跟随新 Catalog。
要完全自定义，用「自定义 Agent」新建一个 ID。

### B4. 会话标题是怎么来的？能改吗？

首行前 N 个字符（N 由 `configs/app-config.toml` 的 `conversationAutoTitleMaxChars` 控制，默认 48），无文字时为「新任务」。只在首次创建时生成，之后可在侧边栏直接重命名。

## C. 运行与状态

### C1. 停止后我发的消息为什么没让工作流继续？

Workflow/AUTO 停止后，composer 是普通输入框，发的消息是 `NonRuntimeControlled`——可以有问有答，但不推进节点。要继续必须点「继续工作流」（或带输入的「继续并发送」）。

### C2. 「继续工作流」和「恢复工作流」差在哪？

- **继续工作流**：当前节点还没完成 → 恢复它的执行。
- **恢复工作流**：当前节点已完成，但"完成 → 跳下一步"之间断了 → 直接做下一步决策，**不重跑**当前节点。

两者互斥显示，不会同时出现。

### C3. Ctrl+C 关掉程序了，任务还能继续吗？

可以。程序退出会把运行中的会话暂停为 `process-interrupted`，重新打开后在对应 run 点「继续工作流」即可（CLI 用 `gold-band continue`，若进程是被强杀的要加 `--recover-interrupted`）。

### C4. 为什么有时候点"继续"没反应？

可能是启动握手（最长 60 秒）超时或已被另一次请求占用。会返回结构化错误（`runtime.continue-launch-timeout` / `runtime.continue-stopped-before-start`），等待后再点一次即可。重复点击不会重复推进。

### C5. token 消耗比我预想的高，正常吗？

- Workflow / AUTO 都是"对抗式验证 + 循环"，比直接问 Agent 更费 token，换来的是更少返工。
- AUTO 尤其高：它有提议、并行子任务、合并、验收、再派发多轮。
- 想省钱：把需求压缩、用 Direct 处理小任务、用工作流而不是 AUTO、给 `max_attempts` / `max_rounds` 设上限。

### C6. 上下文压缩是什么？为什么显示"正在压缩上下文"？

是 provider 的上下文压缩阶段，属于 ACP 运行阶段而不是一条普通消息。压缩期间 composer 的 processing 状态会切成"正在压缩上下文"，超过 120 秒会提示"耗时较长"，但不会伪造失败或百分比。
压缩完成后，如果 provider 返回了非空摘要，压缩行会多一个「查看摘要」，在右侧「压缩摘要」Tab 里看（Markdown，可切源码、可复制原文）。

## D. 工作流与 AUTO

### D1. 为什么工作流保存失败，说"多个入口"？

入口由画布拓扑自动派生：没有初始入边的节点是候选入口。**唯一候选**才能保存；零个或多个都不行。
注意：指回 success 主链前序节点的 failure 回退边**不算**入边，`$new-round.new_round_entry` 也不算。

### D2. 为什么不能给同一个节点加两条 success 边？

DSL 规定：同一来源节点的同一结果类型只能有一条出边。要做分支请用 AI 输出验证让节点产生 success / failure 两种结果，或拆成多个节点。

### D3. 改了工作流模板，正在跑的 run 会变吗？

不会。run 启动时冻结了 `workflow.snapshot.json`，改模板只影响之后的 run（以及"下一次 Run"配置）。

### D4. AUTO 一直不结束 / 反复开新轮怎么办？

检查动态控制限制：`maxDynamicNodes`、`maxRounds`、`maxFanout`、`maxDepth`。限制用的太宽松会持续派生。
另外 acceptance 节点判定标准太模糊时容易反复不通过——把验收目标写具体。

### D5. AUTO 的「全局 Goal」有什么用？

非必填，会追加到每个 AI-DYNAMIC 内部节点的目标上。用于"所有子任务都要遵守的额外约束"。
输入内容会保留原始空白（不做 trim），只有纯空白会被当作未设置。

### D6. AI-DYNAMIC 的子任务为什么互不干扰？

每个子任务在自己的 Git worktree 里跑（由 run 级 worktree 机制派生），合并和验收由 merge / accept 节点负责。所以能并行而不冲突。

## E. 右侧工作区

### E1. 为什么"工作空间"和"运行目录"看起来一样？

两者都是文件树，区别是：
- **工作空间**根 = 当前会话工作位置（项目根或 linked worktree），可读写；
- **运行目录**根 = 当前 attempt 目录，展示产物，默认**只读**。
运行目录 Tab 用同一个 Tab 身份，切换 attempt 时原位替换，不会新开 Tab。

### E2. 删除文件是永久的吗？

不是。工作空间文件删除一律移入系统回收站 / 废纸篓，并且目录树聚焦时 `Ctrl/Cmd+Z` 可以还原（每项目最多 20 步撤销历史，仅当前会话内）。

### E3. 源码管理里为什么按钮是灰的？

三种常见原因：
1. 同一工作空间已有 Git 写操作在进行（那时会有旋转态）；
2. Merge / Rebase 正在进行（`locked` 提示会说明被什么操作占用）；
3. 仓库还没有首次提交（需要先暂存并创建首次提交）。

### E4. 为什么会话在 worktree 里，源码管理却显示不可用？

worktree 已被收回或无法解析。Tab 会显示「会话工作树已收回 / 不可用」+ 原路径 +「浏览主工作区」按钮。系统**不会**自动回落项目根，需要你主动点。

### E5. 内置浏览器和系统浏览器什么关系？

独立的零权限子 WebView，有自己的 Cookie profile（跨重启保留登录态）。不是系统浏览器的替代品：不支持扩展、多 profile、下载队列、从系统浏览器导入 Cookie / 历史。
本地 HTML 通过自定义协议加载，越出授权目录的相对引用会提示由你确认放开。

### E6. 为什么 Markdown 里的网络图片不显示？

出于隐私与安全考虑，网络图片默认不加载（加载会把请求发给文档作者指定的服务器，可能暴露 IP）。在图片占位处点「加载」即可，之后该 host 加入「受信任的图片域名」。
官方更新说明不经过这个列表。

## F. 上下文与资源

### F1. 角色（Profile）和 SKILL 有什么区别？

- **角色**：可复用的执行身份 / 指令集，工作流节点通过 `profile id` 引用，作用于"这个节点扮演谁"。
- **SKILL**：Agent 可调用的技能包（`SKILL.md`），通过 system prompt 的 skill catalog 注入，作用于"它会做什么"。
MCP 则提供**工具**（外部能力）。三者同属「上下文管理」但解决不同层的问题。

### F2. 内置角色为什么改不了？

内置角色只读，只能「另存为新角色」后编辑。这样升级客户端时内置角色可以随版本更新而不冲突。

### F3. SKILL 同步到 Agent 时提示冲突？

同一 Agent 的 skills 目录里已有同名原生 skill，或同目录正在创建 / 重命名同名项。系统直接阻止，不会覆盖你的原生文件。
注意：文件系统身份是**目录名**，而展示用的是 front matter 的 `name:`，两者可能不同。

### F4. MCP 显示🟡需要授权怎么办？

该 server 的 OAuth 凭据缺失或过期。在 MCP 配置里完成授权后重新诊断。
MCP 采用「先保存 → 再验证」，所以配置能存进去，但只有握手成功才变绿。

### F5. MCP 卡片为什么显示某 Agent 不支持？

per-Agent 兼容性来自 Agent Registry 的能力快照。注意两条规则：
1. Agent 健康状态优先——不健康的 Agent 显示"不可用 + doctor 失败原因"，**不能**说成"不支持某 transport"；
2. 健康但没声明 `mcpCapabilities` 的 Agent 显示未知态，可以手动重新诊断。

## G. 定时任务

### G1. 定时任务算第四种运行模式吗？

不算，它是**触发层**。到点触发 Direct / Workflow / AUTO，产物仍是 `task → run → round → attempt`。

### G2. 创建定时任务会立刻跑一次吗？

不会。只保存定义，首次到计划时间才物化 Task 并执行。想马上跑用「立即执行」，它不改变下一次计划时间。

### G3. `new` 和 `continuous` 会话策略怎么选？

- `new`：每次都是干净的新会话，适合"每次独立分析一份数据"。
- `continuous`：同一 ACP 会话持续追问，适合"持续跟踪一件事"。仅 Direct 支持。
  注意 continuous 模式下改 instruction / 附件会保留 Task 链，但改 workspace 或 Direct Agent 必须新建定时任务。

### G4. 为什么定时任务到点没跑？

看状态：`已跳过`（队列保护）、`已错过`（应用当时没运行）、`需要处理`（有异常需人工看）。
另外「保持系统唤醒」只阻止**空闲导致的系统睡眠**，允许屏幕休眠；应用没运行时不会触发。

### G5. 定时任务的执行记录能保留多久？

默认 30 天，可在设置里改 1–3650 天。清理只删诊断类记录（未接受的 succeeded / failed / skipped / missed），accepted 执行历史与活动 Run 不删。

## H. IM 与协作

### H1. 为什么企业微信一直显示"等待绑定"？

WebSocket 在线 ≠ 可投递。必须由**授权账号**主动给机器人发过一条私聊消息，形成 canonical 私聊 binding 后才会显示「可用」。

### H2. 在手机点了"同意"，桌面端还会弹权限卡吗？

已有一次被接受后，其他端会收敛到同一终态（显示已处理）。只有"先到"的那次写处理结果，重复点击不会重复执行。

### H3. 能在 IM 里让我电脑上的任务"重新跑"吗？

不能。IM 只支持三类干预（权限、追问、人工 check）+ 信息通知。启停 / 重跑 / 编辑工作流 / 执行命令都不支持，也不做自然语言解析。

### H4. 支持微信群吗？

不支持。只支持一对一私聊，且一个渠道只绑定一个机器人、一个授权用户。

### H5. 为什么"用户反馈"入口有时候看不到？

那是渠道能力：`feedbackEnabled` 经 `AppInfoVm` 控制，当前 WB 渠道开启、默认渠道关闭。前端不按渠道名猜，后端命令也会再校验一次。

## I. 数据与安全

### I1. 我的代码和对话会被上传吗？

- 过程数据全部在本地 `~/.gold-band/`。
- 会外发的只有：Agent 本身调用模型时发送的内容（由 Agent / Provider 决定）、你主动提交的「用户反馈」（含日志尾部 512 KiB）、以及渠道开启时的匿名指标上报（不含 prompt 正文）。
- 日志里不写 prompt 正文、文件内容、命令参数、路径。

### I2. 能给同一个项目加两次工作空间吗？

不会重复。工作空间身份由规范化路径生成 `projectId`，Windows 下不区分盘符 / 路径大小写。

### I3. 升级后我的配置会丢吗？

不会。用户级状态用 `stateSchemaVersion` 做一次性迁移，达到当前版本后启动直接跳过迁移扫描，迁移函数本身幂等。
内置 Agent 的命令 / 参数在升级后会被新 Catalog 覆盖（这是设计行为），自定义 Agent 配置不变。

### I4. 我手动改了 `run.json` / `node.json` 怎么办？

这是 canonical state 文件，改错可能导致 run 无法恢复。建议先备份 `~/.gold-band/projects/{project-id}/`，再在界面上重跑该任务。

## J. 开发相关

### J1. 加一个新 Agent 要改多少代码？

通常不用改 runtime。在 `configs/agent-catalog-policy.json` 相关的 Catalog 生成链路里加入该 Agent 的 ID / npx 包 / 版本，重新生成 Catalog 即可；用户在 Agent 管理里选择它。

### J2. 为什么改提示词要动七个语言目录？

七个语言目录的相对路径必须一致，角色缺某语言时降级到英文。CI 会校验。另外 CI/CD 角色正文、`cicd-goal.md`、`runtime/remote_task_*.md` 只保留简中 + 英文。

### J3. 可以给错误文案直接在 Rust 里写中文吗？

不行。后端只返回结构化错误（`code` + `params`），文案全部在前端 locale 里按 code 本地化。

### J4. 前端能直接读 `themeId` 来改样式吗？

不能。业务组件只消费语义 role 与主题 token，主题包负责换色不负责改结构。

### J5. 我改完 UI 怎么验收？

涉及页面 / 路由 / 交互 / 布局时，必须启动前端验证，优先 deep link 到目标页面，验证后清理启动的测试资源。桌面客户端级交互才用桌面控制工具。

## K. 我遇到的问题不在这里

1. 看 [状态与恢复指南](../02-practice/04-状态与恢复指南.md) 与 [数据目录与诊断](../02-practice/05-数据目录与诊断.md)。
2. 打开会话页「原始帧」看 Agent 实际收发了什么。
3. 设置 → 高级开启「记录详细日志」，复现一次，再看 `~/.gold-band/logs/runtime.log`。
4. 帮助 → 用户反馈，勾选关联会话并上传日志尾部。
